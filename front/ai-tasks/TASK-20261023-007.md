## Implementation

`localization/catalog.ts` holds keyed English/Chinese UI messages; `messages.ts` formats only UI/status descriptors and exact known runtime phrases. User/model messages, conversation titles, provider/model/file names, API IDs and actual paths are never translated. Chat navigation, engine handoff, attachments, context tokens, collapse/drag controls, error boundary and optional application Git/restart/version controls use the catalog. English/Chinese accessible labels, dates/numbers and document language follow the same preference.

A single React provider remains mounted around App and ChatDock. The language controller initially uses the browser language plus guarded local fallback, then reads the project preference through GET /api/runtime/language. Explicit selection renders immediately and saves with POST {language}; queued writes are serialized and obsolete pending writes skipped. An epoch prevents a late initial GET from undoing a click. Same-value iframe echoes and iframe updates while a save is pending or failed cannot clear the local choice or retry state. Failed saves keep the current page language and expose retry/details; no credentials enter storage. Storage denial/offline legacy runtimes retain a useful fallback. No page reload, new model request, composer reset, session switch or subscription change occurs on language selection.

The optional kernel iframe host uses `saplingagent:language` messages with exact origin and known frame contentWindow checks. It sends the current language on changes/load; received messages update the page without reposting the preference. Kernel controls only notify their parent after an explicit successful save, not initial load. Help opens the same-origin /__saplingagent/help?lang=... route.

Errors use the shared kernel `describeError` classifier for localized explanations and next steps. Expandable details preserve the original code/message with shared credential redaction. Known local validation/attachment explanations use catalog entries. The request hook retains structured causes/codes instead of losing them in concatenated display strings. Transcript and tool operation payloads are unchanged.

No new dependency, service, port, model, permissions restriction, default Git control or version increment. TypeScript enables TS extension imports under its existing noEmit/Bundler configuration to share source helpers with Node24 fixtures. Dependencies/runtime were locally APFS-copied for testing, not linked to an external checkout or changed in manifests.
