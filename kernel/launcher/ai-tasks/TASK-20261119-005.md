# TASK-20261119-005 — Reduce idle status polling

The macOS Dock launcher checks for project maintenance locally every two seconds, uses the authenticated status helper at a 20-second interval while settled, and checks promptly while starting, reopening or quitting. The browser runtime status page suspends automatic requests while hidden and refreshes on return.

On macOS ARM64 with Node 24.21.0, 15 launcher integration, native Dock and runtime status tests passed. The native fixture verifies no repeated status helpers during a 4.5-second idle sample and a timely response to a maintenance request. Existing native apps need a rebuild to receive the AppleScript change.

## Two-project integration

On Debian ARM64 in Docker, two clean copies using external-only MCP served their actual React page and JavaScript on independent ports. After warming the Vite caches, the same two projects were sampled 15 seconds after serving requests. Their complete owned process trees in development had 10 processes, 184 threads and 584 MiB proportional set size (735 MiB summed RSS). Static mode had 8 processes, 88 threads and 241 MiB proportional set size (360 MiB summed RSS). These are single-host, post-build samples. Cold builds and AI inference have different resource costs. Both modes also passed the two-project start, serve and independent-stop checks on emulated Debian x64. In every case the second project stayed ready when the first was stopped.
