## Scope and design

The owner authorized a minimal cross-platform project status page after app
activation. This subtask provides only native preparation feedback while the
runtime page is not yet available. It changes `native/`, its focused test and
`REFERENCES.md`. Root owns shared contracts/guides/manifest/JS and runtime-manager
work is a separate task. No release/Adobe/customer upgrade, version increment,
account/model operation, new persistent app service or permission restriction.

macOS uses a small AppKit window in the existing ordinary Dock applet. Preparation
is non-modal; closing the window hides it, and reopening while the helper is busy
shows it again without creating another helper. Existing status phases update its
text; ready/stopped hides it. Existing normal Quit and configuration handoff retain
the owned helper/runtime shutdown contract. No Terminal/tail process is added.

Windows uses standard Win32 controls through Go's standard library, on one locked
UI thread. WM_CLOSE hides the display without cancelling startup. Node still uses
its existing detached process group, with stdout/stderr in the project launcher
log. The display reads only new, complete, fixed `SAPLING_PROGRESS:` lines from
that log and immediately closes each read handle. Unknown/provider/credential
output never appears in the progress window. Buffering is bounded.

The closed vocabulary is checking/installing/starting/status/ready/failed.
TASK050 emits `status` only after the actual gateway is verified and its URL is
opened or printed to the log. That marker releases the native Windows helper and
its executable/log handles while Node continues preparation under its existing
leases; it does not claim all services are ready or that the browser succeeded.
Worker failure before takeover displays a fixed system PowerShell error prompt
from the project parent and releases the Go executable immediately. The prompt
does not open a project file or keep the project working directory. No new shared
progress file or hidden startup worker is introduced.

## Remaining limits and next step

Windows native GUI, file-lock/antivirus behavior and real hardware acceptance are
unverified; cross-compilation does not establish those. Before gateway takeover,
existing install/runtime leases serialize configuration; an OS sharing refusal
retains the folder and requires retry after startup exits. The separate popup no
longer holds the project launcher executable indefinitely. Forced termination is
not equivalent to orderly Stop/Quit. No human acceptance is claimed.

Root integrates this commit with TASK048/050, updates shared guides/contracts and
the maintainer manifest, performs combined validation and updates main. Existing
exported apps require an explicit rebuild to gain this native behavior. Public
