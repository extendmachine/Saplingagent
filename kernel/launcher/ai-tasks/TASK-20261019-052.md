## Cause and correction

Read-only inspection of the reported customer app found no locale variables in
its Finder-started environment. Under the resulting C locale, macOS `ps` escapes
Unicode executable paths as `M-...`; the existing exact realpath check therefore
rejects the real app with `DOCK_OWNER_INVALID`. The compiled AppleScript retained
its initial missing-value properties and valid signature; stale saved PID
properties were not supported by the evidence and were not changed.

The single production behavior change supplies `LANG=en_US.UTF-8` and
`LC_ALL=en_US.UTF-8` to the `ps` child only. This keeps executable bytes and the
English start timestamp stable across Finder and user time locales. Parent and
system environments, strict realpath/PID timestamp/project/nonce checks, startup
cancellation and ownership-based shutdown remain unchanged. Existing exported
apps use the corrected JavaScript bridge without a native rebuild.
