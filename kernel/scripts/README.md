# Project-local launcher and source delivery

`Saplingagent.sh` is the single bilingual user entry on macOS and native Windows (Git Bash). Run `bash Saplingagent.sh` in the complete application folder. Install / update prepares pinned Node/Codex/OpenCode and locked local dependencies; Configure AI opens a standalone React configuration page; Start app supervises owned chat services; Diagnostics checks installation/configuration without inference. See the root README and OS installation guides.

## Configuration boundary

`kernel/scripts/launcher/cli.mjs configure [--no-open]` checks the minimal kernel and initializes project-local runtime metadata without importing accounts. Short-lived A prepares the closed configuration backend and built `kernel/ui/setup` assets, copies them with an independent Node executable outside the project and launches B. A exits once B publishes its loopback address. B owns setup, project rename and native launcher compilation; credentials and outputs remain in the project. Finish setup starts project-local A with the cleanup receipt; B exits and A removes its verified temporary bundle after process exit. Closing a browser tab alone does not stop B. The app checks/installs application dependencies when the user opens it. See `kernel/configuration/CONTRACT.md` and `docs/project-launcher.html`.

Saved account/API schemes live in local-secrets; shared `kernel/contracts/ai-configuration.mjs` adapts them for Agent startup. A selected API or OpenCode scheme does not require ChatGPT login. Legacy explicit `login`, `opencode`, `logout` recovery commands remain. Running sessions are not rebound to changed providers; restart and create a new conversation after configuration changes.

## Runtime and package boundary

The launcher selects the pinned OS runtime within `.runtime/`, npm cache within `.cache/npm/`, and dependencies within each source module. It does not install globally, alter permanent environment settings, elevate permissions or import another project's credentials. Direct development commands in scripts/ remain internal maintenance tools; the supported recipient entry is the root Bash launcher.

`scripts/dev.mjs` owns the runtime-manager, persistent public gateway (5173), internal Vite (5174), Agent (4310), workspace (4311), builder (4312), optional PDF (4313) and OpenCode (4315). Restart app/backends and recovery routes follow kernel/services/runtime-manager/CONTRACT.md; do not kill unrelated services by port or name.

Source packagers export an explicit Git commit into a clean macOS/Windows ZIP with checksummed files, all rules/Skills/source/dependency declarations and fresh recipient records. No private state, installed dependencies, logs, worktrees or developer approvals. They are source deliveries, not offline model bundles or Clawtask imports. See kernel/scripts/macos/README.md and kernel/scripts/windows/README.md for OS contracts and honest pending native validation.

## Historical release bootstrap contract (TASK-20261013-001)

Root install.sh is a standalone Bash3.2-compatible new-folder downloader, separate from the one persistent Saplingagent.sh menu. Supported hosts: macOS Terminal and Windows Git Bash; flags --dir PATH, --lang en|zh, --download-only. It resolves only GitHub refs/heads/release over HTTPS, pins a40-character commit SHA, downloads/extracts the GitHub commit tarball into owned staging, validates archive paths/types and required complete-folder files, and reserves a fresh destination without merging into existing source. No Git history/global install/credentials/model request in the download. It records delivery.json sourceRef/sourceCommit/release Git defaults and initialization hashes. Failed downloads clean owned staging and preserve their failure status. New targets remain if a later installation fails; retry the existing Saplingagent.sh installer.

With an interactive terminal, restore /dev/tty as child input so curl | bash does not consume menu/Git selections as script text. Both install and the existing menu run in foreground; Windows native bridge remains unchanged. Noninteractive callers can use --download-only and start the launcher later. Install prepares current OS dependencies, calls shared recipient-records.mjs before Git setup to initialize unchanged fresh goal/task/AGENTS records once, and keeps pre-install customer records/Git with a warning. Packager uses the same helper without changing package manifests or source-record meanings. No developer acceptance transfer.

Follow mode replaces remote.upstream.fetch with a single selected-branch mapping and sets --no-tags; explicit branch overrides remain, saved-mode reinstall/current versions preserved. Fresh default release delivery never imports author main/testcode refs; previously imported branches are not deleted. Local empty main is independent customer history. This is source selection/Git configuration, not an Agent sandbox, path restriction or ban on explicit Git commands. Public branches remain manually accessible. Source updates remain deliberate; this bootstrap refuses existing targets.
