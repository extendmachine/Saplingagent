## Implementation

- Claude has API key and Subscription token (personal use) radio choices. The
  subscription branch contains name, masked token and model ID/alias only.
- Subscription excludes API URL/protocol, no-auth, limits, discovery and API
  credential imports. The explicit payload helper omits all those fields and
  response-only `hasKey`, while retaining revision/ID/activation semantics.
- Direct editing of a saved subscription preserves its kind and permits an empty
  token only for that saved credential. Cross-kind/engine transitions clear the
  saved-credential hint and require new input; switching back also conservatively
  requires input. Tabs, presets and authentication changes clear typed secrets.
- Existing dirty-form validation and Save & build callbacks include subscription
  drafts. Scheme labels identify account/API/subscription and saved token status.
- English/Chinese guidance explains the user's own `claude setup-token` flow,
  local write-only storage and current provider terms without promising access,
  token lifetime, quota or permission to distribute subscription authentication.
  Existing account, API import and external MCP paths remain available.
- Localized KEY_REQUIRED/INVALID_CONFIG messages cover subscription inputs.
