## Authorized behavior

The existing account/API/Claude controls gain a parallel External AI / MCP tab.
The independent stdio service is not a fourth built-in model provider. Users can
enable it and select external-only mode without a built-in account. Full Access is
described as current OS-user file/shell/context/Skills access, including accessible
external paths, without root/admin elevation. External clients retain their approvals.
External-only users converse in their own client; the web chat has no model.

MCP settings and revision are independent from profiles. Saving only sends revision,
enabled and externalOnly; no generated path, credentials or global client settings.
Save & build saves dirty MCP settings before finalization, and new MCP revisions
invalidate finish/export readiness through the existing server snapshot flow.
The ready formula is activeId OR enabled-and-externalOnly; an actual launcher and
server exportReady are still required. The external cleanup acknowledgement remains
unchanged. Profile saves do not write MCP choices.

The MCP component remains mounted across tabs so pending choices are retained.
Old refresh results cannot overwrite a newer save. Explicit Reload saved MCP settings
discards the local choices; conflict responses otherwise keep them dirty. Copy and
download are disabled during unsaved changes, unavailable dependencies or busy setup.
Clipboard failure is visible without success. Both exports fetch the current path
again; project root/artifact/compile-time changes refresh the displayed configuration.
Users are told to save/build before export, update their external client's old paths
after rename, and disconnect MCP before maintenance/rename to release Windows handles.
English and Chinese labels/workflow guidance are provided.
