# TASK-20261119-002 — Reuse public npm tarballs across projects

Shared mode seeds npm's local cache from SHA-512-verified public tarballs.
Regular setup, native dependency repair, the legacy installer and offline
kernel maintenance use the bridge. npm install scripts and node_modules still
run within their own project. The fixed maintenance worker sources include
the bridge and reviewed package fingerprints. The configuration host includes
both in its generated module closure.

All 397 unique tarball URLs and SHA-512 values across the seed kernel, frontend
and MCP lockfiles matched the anonymous npm public registry version metadata.
On macOS arm64 two clean MCP projects installed 96 packages apiece, with 93
content blobs published after the online install and a successful second
installation using npm ci --offline. Both installed SDK 1.32.1.

The offline fixture exercised independent node_modules, private/mixed locks,
unreviewed and portable installs, concurrent publication, corrupt content,
failure and an abort. Both cache tests passed on macOS and Linux arm64
(Debian, Docker with networking disabled) using Node 24.21.0. The existing
macOS tools, dependency repair, shell installer and maintenance suites passed
62 checks. Native Windows execution remains unverified. The integration owner
updates the kernel manifest after combining the service changes.
