## Confirmed problem and scope

The user identified the Drone app as unable to Quit. Its launcher recorded
`KERNEL_BUSY` while the runtime was ready and the Agent had no active runs.
Its gateway source was byte-identical to main. A disconnected browser could leave
a mutation's upstream response unconsumed and its write count pending indefinitely.
A separate before-headers path released the count before the upstream work finished.
The reviewed fix drains abandoned write responses and releases accounting exactly
once at upstream termination. Existing service preparation, active-work, ownership
and authentication checks remain in effect. This does not force Quit during real work.

This integration regenerates the maintainer manifest and adds this handoff only.
The manifest gains one regression-test entry (226 to 227); only the four changed
service source/documentation records also change. Kernel version and mirrors remain
0.9.5. No UI, native binary, engine, dependency or permission change is required.
