# TASK-20261117-007 — Interruptible maintenance handoff and recovery locks

Codex worked in the detached repair17-maint worktree from main 9e6939d. The coordination worktree records ownership and integration. This change keeps kernel version 0.9.9.

The gateway checks the connection after draining and after worker startup. It sends the begin message and shuts down the application after the HTTP 202 response finishes. Cancelling before that point waits for the owned child to exit, removes its matching lease and releases the service gates. The standalone recovery helper checks the inode and device before removing a lock it failed to initialize.

Regression coverage exercises disconnects during draining, worker copying and response writing, a replacement maintenance lease, and failed recovery lock writes with and without replacement. The maintenance suite includes a loopback HTTP handoff, detached workers and a fixture application. Recovery tests use synthetic saved source. Native Windows execution and customer data were outside this verification. The coordinator regenerates and verifies the combined manifest before main integration.
