# Independent kernel package contract v2

TASK-20261016-001,2026-10-16. Kernel is project-local platform tooling with no daemon/port. Public library exports are in kernel/manager.mjs; the launcher calls kernel/cli.mjs as a separate command. Metadata and startup interlock are shared contracts/kernel.mjs, not another service's private implementation.

Manifest kernel/manifest.json: schemaVersion2,version0.90,appApi1,minNode,notes and files[{path,sha256,bytes,executable}]. Exact membership is defined by isKernelPath in contracts/kernel.mjs. Kernel owns install/update tooling, Git management, complete process restart, AI configuration/engine adapters and their explicitly declared shared contracts. The mixed Agent HTTP/chat entry, application frontend entry/styles/build/dependency files, chat UI, workspace/context, builder/page reading, MCP runtime and all Skills/plugin registrations are application-owned. Their source remains in the complete distribution, freely editable and outside kernel update/deletion/restore. Runtime/services config,rules/AGENTS/goals/records,data,secrets,Git metadata,logs and installed dependencies remain excluded. Full Access is unchanged; membership is an update package boundary, not a tool permission boundary.

Schema2 deliberately refuses the earlier broad schema1 manifest. An old updater also rejects schema2 before interpreting released application files as kernel deletions. Use the new complete management tooling and its reviewed schema2 baseline once when moving from the unreleased broad prototype; never regenerate a customer's baseline to hide local core edits. Current check/apply refuses obsolete broad baselines/plans; current restore preflights every entry and refuses out-of-scope or schema1-manifest backups before any source write. Reconcile historical backups deliberately while retaining application files. No automatic removal/migration of released modules.

kernelStatus(root) returns baselineVersion,version,appApi,sourceCommit?,installedAt?,state (managed|legacy|invalid),lastBackupId?,warning?. No secrets or conversations. Read-only Agent GET /api/kernel returns {kernel:status}. Footer uses version with0.90 fallback.

checkKernel/prepareKernel: resolve official extendmachine/Saplingagent release commit through public GitHub HTTPS, fetch its manifest and individual owned files at that immutable SHA, enforce hash/size/path/schema/Node/appApi compatibility. No Git fetch/remotes/checkouts or credentials. Persist candidate bytes and before-hashes in ignored .runtime/kernel/plans/<UUID>/. Return plan ID,target version/revision,changes,conflicts,compatibility warning; no source changes. Absent release manifest is KERNEL_UNAVAILABLE, not success.

applyKernel(root,planId,{acceptRisk:true}): hold shared operation lock, refuse this app's live runtime/install or changed local baseline/plan, refuse symlinks/path escapes and conflicts. Explicit risk acknowledgement is part of this update operation, not an Agent access policy. Save original owned bytes/modes/state to ignored .runtime/kernel/backups/<UUID>, retain standalone recovery helper, then atomic per-file replacement/deletion. No business/data/Git write. Journal partial failures; never report ready or auto-rollback. Last write is manifest/state. A source update is distinct from dependency repair/application readiness. CLI prints backup/recovery and dependency-repair instructions. No automatic startup or model call.

restoreKernel(root,backupId): explicit action only, hold same lock, app stopped, reject changed post-update files before restoring originals. Partial updates accept recorded before/after versions; later user edits are never silently discarded. An independent copied .runtime/kernel/recover.mjs provides recovery if new launcher/kernel fails. Source-only restore cannot undo business data migrations, external actions or guarantee dependency/model compatibility; repair old dependencies and restart/check manually.

Errors: INVALID_KERNEL/INVALID_PATH/INVALID_PLAN400; KERNEL_CONFLICT/KERNEL_BUSY/KERNEL_INCOMPATIBLE409; KERNEL_UNAVAILABLE/network errors502; KERNEL_INTEGRITY/partial I/O errors500. Report paths/status, never credentials/raw remote response. Normal metadata logs in logs/kernel-manager by day,30-day retention; no payload content. State/backups stay local and ignored, without automatic cleanup.
