## Implementation

GET/POST `/api/config/mcp` delegate only to the shared builtin contract
`kernel/contracts/mcp-access.mjs` owned by TASK003. GET state and provider/import
mutation replies include the minimal MCP summary. MCP revisions are independent
of provider revisions and no MCP model profile is created. Successful settings
writes invalidate setup readiness; malformed/stale writes retain saved state and
do not falsely invalidate a completed setup. Existing Host/Origin/Fetch Metadata,
token and body limits remain. In-flight MCP writes participate in directory/build/
close reservations and pending OAuth/import guards.

Finalize/build accepts an active provider or enabled external-only MCP mode. It
does not require credentials or make a model request for MCP-only setup. Generated
client configuration is recomputed from the currently rebound root after a rename;
persisted MCP settings contain no absolute source location or credential. Missing
local dependencies are reported as availability warnings, not connection success.

The setup fingerprint adds the MCP file bytes with a domain separator only when
the file exists. Existing installations with no MCP record retain their exact
previous fingerprint. Explicit enable/edit/disable then invalidates old completion
receipts. Legacy rename checks MCP owners after acquiring its operation lease and
after the ordinary offline check; a live connection is retained and the rename is
refused, without killing the client host or losing its ownership metadata.
