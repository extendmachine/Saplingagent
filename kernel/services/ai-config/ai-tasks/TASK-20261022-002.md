## Implementation

The existing profiles endpoint accepts `engine:'claude',kind:'subscription'` with
the write-only apiKey input carrying a manually generated setup token. Persisted
metadata has id/label/engine/kind/model only; summaries add hasKey. The credential
file contains oauthToken, while the ledger references its category/personal purpose
without copying secret values or claiming an expiry date.

New or cross-kind subscriptions require a token. Same-kind blank edits retain it
only after validating the existing private credential; missing, malformed or
API-key-only storage requests re-entry with KEY_REQUIRED. Token bounds/control/
internal-whitespace checks and explicit refusal of API/noAuth/token-limit fields
prevent accidentally mixing authentication methods. API key behavior is retained.
Subscription model discovery returns INVALID_CONFIG before any network or storage
operation. Existing HTTP guards, setup-readiness invalidation, revision and shared
writer lease are reused without a new endpoint or server lifecycle.

API import remains distinct: overwriting a selected subscription with an explicitly
imported API credential still needs replace:true. Changing a scheme deliberately
replaces that scheme's private credential type; another scheme is unaffected.
Configuration writes remain individually atomic, not a multi-file transaction.
