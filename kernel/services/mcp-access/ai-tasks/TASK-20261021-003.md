## Scope and decisions

User clarified external AI should obtain current-OS-user Full Access through MCP.
Coordinator selected a standalone8tool kernel service, avoiding dependence on
customer application MCP or internal model credentials. Strict stdio; no HTTP
listener, model prompt, app startup or external client-config write. Existing
application16tool MCP stays unchanged. No path/extension protection or approvals.
File write/delete provides no implicit snapshots. Commands preserve actual status,
bounded output and cancellation; completed effects cannot be rolled back.

Shared builtin-only module persists enabled/externalOnly with revisioned atomic
configuration writes and generates final-root pinned-Node connection JSON. It
owns client receipts and lock-coordinated registration. Maintenance callers hold
the same kernel-operation lock while invoking assertMcpClientsStopped and making
incompatible changes; active/unknown client ownership blocks without host killing.
Normal disconnect waits for dispatched writes and owned command shutdown before
deleting only its own receipt. Full Access paths are separate from managed storage.
