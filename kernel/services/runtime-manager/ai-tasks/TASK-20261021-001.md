## Decisions

The response lifecycle listeners are registered before consumption. When a mutation's
browser leaves before headers, the eventual response is drained rather than destroyed.
When it leaves after headers, unpipe the closed destination and resume consumption.
Browser close and completed request upload never release write accounting themselves.
Response end, aborted, error and close share the existing idempotent finish function.
A request that terminates before receiving any response also releases its own count;
the request-close fallback cannot prematurely finish an existing streamed response.
Read-only cancellation retains its prior upstream cancellation behavior.

Transport failure does not establish business completion. Existing service drain
checks still run before shutdown/restart; no gate bypass or blind counter reset was
added. An already-running old controller requires an inspected cold restart to load
the corrected gateway; editing source does not fix its in-memory stranded count.
