Configure your AI

Kernel0.9.5 workflow: script → local kernel → web project/AI setup → customer-local native compilation → double-click launcher. Project launcher guide. Use the release-branch download for this version; older menu instructions below describe the previous tooling.

Open the independent setup page

Install the complete application folder first. Run bash Saplingagent.sh, then choose 2. Configure AI. The launcher builds and opens a separate local React page; chat services do not need to be running. Windows requires Git Bash. The same page has English/Chinese controls and opens in the launcher's selected language.

bash Saplingagent.sh configure
bash Saplingagent.sh --lang zh configure
bash Saplingagent.sh configure --no-open

If browser opening fails, copy the printed http://127.0.0.1:<assigned-port>/ URL. Finish all changes, choose Save & build app, wait for completion, then Finish setup. Close setup only closes management. Closing the browser tab leaves setup running. Close setup and Stop app are separate actions. Saving a scheme alone does not restart chat; the explicit Save & build app action stops this owned application before renaming and compilation. Finish setup hands back to A, which removes B after exit; open the app to check dependencies and start.

ChatGPT account

  1. Select ChatGPT account and Sign in with ChatGPT.
  2. Complete sign-in on the official page; this local form never asks for a password. If the new tab is blocked, use Open sign-in page. Use device code offers the official device-code flow when eligible.
  3. The page polls completion and saves/selects the project-local ChatGPT scheme. You can cancel the owned sign-in. Existing local ChatGPT credentials can be selected with Use saved account.

Credentials live in local-secrets/codex/; global Codex accounts are not imported automatically; the explicit import controls below can copy a file-based login into this project. Account/model eligibility and limits are determined by your own plan. Saving credentials does not prove working inference. This is the existing local Codex authentication integration, not a completed commercial Sign in with ChatGPT client registration.

Import an existing Codex login

  1. In ChatGPT account, select Use local Codex login or Upload auth.json.
  2. Local discovery reads the caller's CODEX_HOME/auth.json, otherwise ~/.codex/auth.json (Windows: %USERPROFILE%\.codex\auth.json). A desktop or keychain-only login may have no file: use official sign-in instead.
  3. The clicked import button shows progress. Import success or an actionable error appears directly below the import buttons. If this project already has credentials, choose Use saved account to keep using them, or select the replacement checkbox and retry to import again.
  4. An existing project credential is preserved unless you select Replace existing credentials. Imported login is stored in local-secrets/codex/auth.json and selected as default; the original file stays unchanged.

Files must be valid ChatGPT token JSON and no larger than32KiB. API-key-only files use the API form. Credentials never return in state responses or browser storage. Import confirms local storage only; expired/revoked login, network and quota require actual account use. Save settings, build and finish setup; create a new conversation when changing providers.

Import Claude API credentials

Select Claude API, enter your provider URL/model, then Import local Claude API credentials or Upload API credential JSON. Local sources: ANTHROPIC_API_KEY inherited from the launcher terminal, otherwise env.ANTHROPIC_API_KEY in user settings.json under CLAUDE_CONFIG_DIR or ~/.claude (Windows user profile). Only API fields are extracted; no settings hooks or credential scripts execute.

{
  "apiKey": "YOUR_API_KEY",
  "baseUrl": "https://api.anthropic.com/v1",
  "model": "YOUR_MODEL_ID"
}

Equivalent ANTHROPIC_API_KEY or env.ANTHROPIC_API_KEY fields are accepted. URL/model can come from the form; explicit nonblank form values win. Replacing a saved scheme key requires its checkbox; create a new scheme to keep both. Claude Code .credentials.json subscription OAuth and OS keychain login are not supported: Anthropic requires prior approval for third-party subscription login. Use your own API key or compatible gateway. Maximum32KiB; storage under local-secrets/api-keys, no automatic model test.

API and custom providers

  1. Select API / custom provider and name your scheme.
  2. Choose an engine and protocol. Codex App Server requires a Responses-compatible API. Claude Agent requires Anthropic Messages and an API scheme. OpenCode supports Chat Completions, Responses and Anthropic Messages through its native provider configuration.
  3. Enter the provider's API Base URL, for example https://api.example.com/v1; do not use its website homepage or append /chat/completions, /responses, /messages or /models.
  4. Enter your API key, or select This endpoint does not require an API key for an anonymous local service. Keys are stored in private project files and never read back into the form. Leave the key blank when editing to retain it; changing to no-key retains the old private key but disables its use.
  5. Enter the exact model ID. Fetch models performs an optional authenticated catalog GET, never a model prompt; if unsupported, enter an ID manually. Select a model supporting streaming and tool calls for code modification. Model limits must match the provider's declared capacity.
  6. Select Save & use. Multiple named schemes can be saved; choose Use to change the default. This saves configuration, without testing billable inference.

Use the saved scheme

Choose Save & build app, wait for completion and then Finish setup. Claude Agent, OpenCode-only and custom Codex API configurations do not require a separate ChatGPT login. Startup checks the selected engine/MCP; a connected catalog does not prove provider quota or tool compatibility. To verify inference, explicitly send your own test message.

If chat is already running, restart it after saving and create a new conversation. Existing conversations retain their original engine/model; do not resume a Codex thread through a different provider. No automatic resend, inference, fallback or restart is performed by setup.

Claude Agent

The official Claude Agent SDK runs locally with native tools, project MCP and Skills. Use your own Anthropic API key or compatible gateway and exact model ID. The recommended API Base URL is https://api.anthropic.com/v1; custom prefixes ending in /v1 are supported. SDK state/transcripts stay in local-secrets/claude/. No global Claude Code installation or claude.ai subscription login is used. An anonymous endpoint receives an inert placeholder API header; only select no-key when that endpoint explicitly supports it.

API usage follows your provider billing. Native initialization does not verify quota. Native question dialogs and MCP elicitation forms are not rendered; questions are asked in ordinary chat. Official SDK and terms; Authentication guidance.

Local files and recovery

Profile metadata: local-secrets/ai-config/connections.json. Keys: local-secrets/api-keys/ai-<id>.json. Credential ledger: local-secrets/notes/project-secrets.json (file references only). No keys in public config, CLI arguments, browser storage, logs or source ZIP. Preserve credentials when sharing diagnostic information.

Validation errors leave existing schemes intact. A concurrent write prompts refresh/retry; stale writer locks are not silently broken. Disk writes are individually atomic, not a cross-file transaction; after an I/O failure reload the page to inspect actual state. Remove a stale local write.lock only after confirming no configuration writer is alive. Malformed credential/profile files are preserved for repair.

HTTP origin/token checks protect the local configuration page; Agent file/command Full Access remains unchanged. Real OAuth, actual provider streaming/tool calls and Windows10 native browser acceptance require recipient testing.

OpenCode echoes internal runtime instructions

If a reply starts with Current permissions: full-access, an older adapter may have rendered a native user-message event as an assistant reply. Source versions containing TASK-20261012-017 bind replies to assistant metadata and the current submitted message, with runtime guidance sent separately as system context. Update the source, restart the backend/app and open a new conversation. Install / update repairs dependencies; it does not download source. Check your branch/version: main receives the maintainer fix, while release downloads contain it only after explicit synchronization.

Keep data/ and local-secrets/; do not choose Git local reset as a chat repair. Existing incorrectly recorded bubbles and native conversation history are preserved. If a fresh conversation reports an API, model or quota failure, verify the provider settings and actual error. The routing fix cannot establish provider authorization. Official OpenCode SDK.

External configuration lifecycle

All configuration runs in temporary B outside the project, using copied code, static UI and Node. It writes settings and generated apps only into the project and rebinds paths after renaming. Finish setup starts project A, then B exits and A cleans its verified temporary folder. Open the app afterward; it checks and installs dependencies automatically. Lifecycle and recovery details.

Project-relative configuration storage

Temporary configuration runs in a session-owned ../sapling-config-… directory beside this project. The terminal prints its location; Finish setup waits for exit before cleanup. Persistent settings, caches and outputs remain local. Directory layout and process locks.

Configuration page recovery

The script, native launcher and saved-settings restart prepare the configuration website before opening it. Rebuilding stages new files first and keeps the previous page and hashed resources available. Missing resources request a page reload; missing index.html reports UI_NOT_BUILT, while unreadable files report UI_UNREADABLE. Run bash Saplingagent.sh configure to retry preparation, or bash Saplingagent.sh install --repair when local build dependencies need repair. Do not delete account files or conversations for this error. An interrupted setup build retains kernel/.cache/setup-build.lock; inspect and confirm that no builder is running before removing only that lock and retrying.
