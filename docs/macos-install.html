Install and connect Codex on macOS

One-command release installation

In macOS Terminal or Windows Git Bash, run from the intended parent folder. Install Git for Windows first on Windows. Bootstrap downloads the exact release snapshot into a new Saplingagent folder, installs locally and opens the existing menu. Configure your own AI access, then Start app.

bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/extendmachine/Saplingagent/release/install.sh | bash'

Use --dir for a new custom folder, --lang zh for Chinese or --download-only to fetch only. Existing targets are preserved. First Install initializes recipient records once; pre-install edits remain. Follow mode limits later ordinary fetches to the selected release branch and skips tags, so author main/testcode refs are not imported by default. Local empty main is independent customer history. Public branches remain manually accessible; Full Access is unchanged.

This is fresh installation, not a source updater. Subsequent launches use bash Saplingagent.sh inside the app. Full instructions.

Requirements

macOS 13.5 or later; Apple Silicon or Intel; a writable folder; internet access to Node.js, npm and OpenAI. ZIP installation needs no global Node, Homebrew, Xcode or Codex desktop app. Git is optional for running chat and required for the Git controls/repackaging.

Your own selected account or API provider must have the relevant model access and available quota. Installer architecture selection is supported for both Mac architectures; this release's local checks run on Apple Silicon. Intel/Finder/OAuth interaction requires validation in the corresponding environment.

What the integration does

React → local agent-runtime → codex app-server --listen stdio:// → project MCP → workspace/app-builder. Agent-runtime initializes JSON-RPC, checks the account/model catalog, creates/resumes threads and streams events to the browser. It configures 15 MCP tools and discovers three project Skills automatically.

No manual Codex desktop MCP configuration is needed. The project wrapper selects CODEX_HOME and local binaries. Existing internal seedagent/SEED identifiers remain compatible. Services bind loopback ports 5173, 4310, 4311 and 4312; public settings are in config/runtime.json.

Full Access permits files/commands accessible to the current OS user, without root elevation, directory allowlists or automatic rollback.

Account costs and commercial use

The local server has no separate server fee; model usage requires your own authentication/quota. The configuration page supports your own ChatGPT account or API scheme. Codex also supports API-key authentication billed separately from ChatGPT subscriptions, and the independent configuration page supports API schemes. Installation/login/model discovery does not prove inference access. Start/Doctor send no model prompt.

Check authentication and current usage limits. No free-tier entitlement is promised.

Saplingagent's license restricts commercial use. In addition, the current local Codex authentication is not permitted for commercial or hosted services. Commercial product release requires separate project permission and an eligible Sign in with ChatGPT integration.

Diagnostics and recovery

bash Saplingagent.sh doctor
bash Saplingagent.sh install --repair
bash Saplingagent.sh logout
bash Saplingagent.sh start --no-open

Doctor reports installation/login/runtime status without displaying credentials or requesting inference. Repair preserves source, authentication and business data. Logout removes this project's login; it preserves application files and conversations.

First-install Git storage

Customer downloads and source packaging default to release. Installation asks for: local-only Git history (no remote), your own existing repository URL (origin), or following the author release (upstream). There are only three choices: 1 Local reset (explicit number required), 2 My own remote, and 3 Follow author release. Choice 1 prints a reset notice, erases ALL existing root Git metadata (commits, branches, tags, aliases, index and config), and initializes empty main with zero commits and no remotes. Application files/data/credentials remain in place. The page shows main and No commits yet; Save version explicitly creates the first local record. Enter does not choose local automatically. Reinstall with a saved choice keeps later history; explicit local setup resets again. Choice 2 explicitly adds or updates origin to your supplied URL. Downloads default to release source. Local setup always starts empty main; own/follow use the configured initial branch.

Menu 5, Git / storage setup, or bash Saplingagent.sh git changes the choice. Stop the running application first. The saved choice lives in local .git/config; reinstall/repair preserves your selected branch/version. A linked development worktree retains its shared configuration. No global Git settings, unattended source update, push, hosted repository creation or PR. Explicit menu1 in follow mode checks and merges compatible source. Local reset also removes custom origin/upstream/mirror links and all previous local Git records. Choice 2 retains unrelated non-author remotes. An explicit branch setting can select another branch; pending changes must be saved before switching. Storage submenu choices 4 and 0 are removed; the main menu still offers Diagnostics and Quit. Older saved keep-existing configurations remain valid on reinstall.

Create your own remote repository first and enter an HTTPS/SSH URL without tokens/passwords. Follow mode fetches author history and anchors the delivered source to its recorded commit; raw ZIPs must match upstream history. An unidentifiable/edited ZIP can use local/own storage or a Git clone. Fetch failure can be retried. Install / update checks tracked upstream source only in follow mode; local/own source remains yours. Manual reconciliation uses git fetch upstream and git merge upstream/release. Resolve conflicts and review recipient goal/task records before restart. Adding follow mode to independent history may require a deliberate merge with --allow-unrelated-histories; setup does not rewrite existing history. Fast-forward-only pull stops on diverged history. Full Access is unchanged.

Unattended first setup: SAPLING_GIT_MODE=local|own|upstream, own remote in SAPLING_GIT_REMOTE, optional initial branch in SAPLING_GIT_BRANCH. Mac version history requires Git (Apple Command Line Tools if missing); Windows Git Bash supplies it. Source ZIPs contain no .git metadata; the installer initializes it after your choice.
