在你的 Mac 上启动 SeedAgent

解压到一个本地文件夹，安装运行环境，登录自己的账号，然后开始对话。初始页面只有聊天入口，应用内容由你和 AI 一起构建。

准备

支持 macOS 13.5 及更新系统，Apple Silicon 和 Intel Mac。首次安装需要连接 Node.js 与 npm 官方站点；登录和模型调用需要连接 OpenAI。你需要自己的可用 Codex/ChatGPT 账号，模型与额度以该账号实际返回为准。

先将整个 SeedAgent-macOS-… 文件夹解压到你有写入权限的位置，例如“文稿”。保留文件夹内所有源码、rules/、.agents/skills/ 和锁文件。可以使用中文和带空格的路径。

三个步骤

1 · 双击 1-安装.command
脚本自动按当前 Mac 架构下载 Node 24.21.0，核对官方 SHA-256 校验表；在项目内安装 Codex CLI 0.146.1 和应用锁定依赖。无需先安装 Node、Homebrew 或 Codex 桌面应用，也不需要 sudo。安装完成后会给出下一步；重复安装会复用已完成的同版本环境。

2 · 双击 2-登录Codex.command
官方 Codex 会打开浏览器，由你完成自己的账号登录。凭据存入此项目的 local-secrets/codex/；脚本不导入开发者或其他项目的认证，不改全局 Codex 配置。已保存的项目认证不会因重复安装而被覆盖。

3 · 双击 3-启动SeedAgent.command
脚本启动本地服务和独立的 Codex App Server，自动加载 SeedAgent MCP 与项目 Skills。确认账号、模型、MCP 和网页均就绪后打开浏览器，终端会显示实际模型以及工具数量。

保持启动的终端窗口开启。按 Control+C 或关闭该窗口可停止本次启动的服务；网页聊天中的“停止”只停止当前对话轮。

macOS 若拦截下载的脚本，可右键脚本选择“打开”。若执行位被解压工具丢失，使用下面的终端方式。脚本不主动删除系统的隔离属性。

cd "/你的路径/SeedAgent-macOS-…"
bash "1-安装.command"
bash "2-登录Codex.command"
bash "3-启动SeedAgent.command"

接入是怎样完成的

网页对话 → 本地 agent-runtime → 官方 codex app-server --listen stdio:// → SeedAgent MCP → 本地文件和命令。你不需要手工配置 MCP 地址，也不需要把应用放入 Codex 桌面的聊天窗口。

每次启动根据当前文件夹重新计算路径，CODEX_HOME 使用项目认证目录，MCP 的根目录与服务端口显式传给 App Server。默认网页为 http://127.0.0.1:5173/，后端使用 4310、4311、4312；全部仅监听本机。修改 config/runtime.json 的端口后重启即可。

本版本沿用用户选择的 Full Access：danger-full-access、approval_policy=never，SeedAgent MCP 自动批准，可按当前系统用户权限修改前后端、MCP、Skills 和其他可访问文件。文件保护与逐次确认未加入安装器；应用的改动按需由用户主动恢复。

固定依赖版本用于保持协议兼容；需要升级时先修改 config/macos.json、安装并验证，再分发。安装和移动文件夹都无需重新注册全局 MCP。

常见问题

现象处理
安装中断或网络失败恢复网络后再次运行“1-安装”。需要强制修复已安装依赖时，用 bash "1-安装.command" --repair。Node 校验失败不会启用下载文件；依赖未全部成功时不会写入完成标记。重装保留源码、项目认证与会话。
提示另一轮安装正在进行先等安装窗口结束。若上次进程异常退出，确认所有安装窗口已关闭，再删除此项目的 .runtime/node-install.lock 或 .runtime/macos-install.lock 后重试。不要删除 local-secrets/。
登录浏览器回调失败在项目终端运行 bash scripts/macos/bootstrap.sh login --device-auth，按官方提示完成设备码登录。账号或管理员可能需要先允许该登录方式。
已有认证，但请求提示过期先运行 bash scripts/macos/bootstrap.sh logout 退出本项目账号，再执行“2-登录”。此操作保留应用文件和会话。
端口被占用关闭你之前启动的本项目终端，或调整 config/runtime.json 中的端口。脚本会报错退出，不会终止其他项目进程。
启动等待超过 120 秒运行“4-诊断.command”，查看安装、登录和配置端口状态。可检查终端错误与 logs/ 中的服务元数据；诊断不发起模型请求、不显示凭据。
模型与文档例子不同App Server 按当前账号的模型目录选择配置首选或实际默认模型。已登录、发现模型和一次成功回复分别代表不同验证阶段；额度与网络以真实调用为准。

移动、保存和分享

先停止服务，再移动整个项目文件夹，重新双击启动。更换 Mac 架构或依赖锁文件后重跑安装。.runtime/ 是项目运行环境，data/ 保存会话，snapshots/ 保存可用恢复记录，logs/ 保存服务日志。

接收者的目标、任务与进度会重新初始化，不继承开发者批准记录。分享应用时使用 node scripts/package-macos.mjs <提交编号> 生成干净源包。该包按明确 Git 提交提取源码与完整 rules，排除真实登录资料、会话、日志、快照、依赖和本地运行环境，附带文件校验清单。接收者安装并登录自己的账号。
