Release preparation and acceptance

Prepared in this candidate

  • English UI, errors, installers, README, project documentation, rules and Skills.
  • PolyForm Noncommercial LICENSE, required NOTICE and third-party license boundaries.
  • English launcher filenames and initialized recipient records.
  • Source packaging includes complete rules, Skills, license notices, pinned lockfiles and per-file SHA-256 manifest; excludes private runtime content.
  • Independent service commits for exact-version review without a fourth named branch.

Local self-checks

Existing frontend, Agent/progress/Git, workspace, builder, MCP and Mac installer checks are run in isolated synthetic fixtures. TypeScript/Vite build and source/package consistency are checked. A synthetic preview makes no model calls and does not write real conversations. See the frozen-candidate delivery receipt for actual results and SHA.

The existing frontend bundle-size warning remains. Local self-checks do not replace user acceptance, Finder/OAuth interaction, Intel hardware tests or actual model-account entitlement.

Review before release promotion

  1. Inspect the English chat page, Git panel, version footer and GFM response.
  2. Read the README's install/login/App Server/costs and licensing sections.
  3. Check the source ZIP, its hash, English launchers and recipient initialization.
  4. Record the exact checked main commit, review results and publication scope under rules 04/09.

Land the checked change on main first, using the maintainer authorization in rules04, then promote the reviewed code to release only within the requested publication scope. Main is for development/testing; release is the public default and source distribution branch. Preserve release-only videos, presentation cases and images; do not make the complete trees identical or reset release to main. Adobe experiments remain independent. A main-only request does not publish release, and a source tag/GitHub release/public visibility change remains a separately scoped action.

Windows candidate acceptance

The native Windows10/11 x64 and ARM64 installer is implemented, with Windows10 Intel/AMD64 as the requested target. Current checks on macOS include synthetic Windows process plans and PowerShell7 parser/menu checks. They do not certify native WindowsPowerShell5.1, Windows10 installation, login, model streaming, MCP edits, Git switching or restart. Validate those on Windows before approving the exact candidate; this task does not authorize other-branch synchronization or publication.

Commercial distribution remains separate

The project license does not permit unrestricted commercial use. Obtain separate project permission and resolve OpenAI's commercial/hosted authentication requirements before commercial product distribution. This version does not implement commercial Sign in with ChatGPT registration.

Cloud synchronization, Linux delivery, a signed native .app and proven automatic long-term layout improvements remain future scope.
