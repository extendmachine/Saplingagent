Reuse local tools and one user library

Installation prepares Node and the setup page. Choosing Codex, Claude Code or OpenCode prepares the selected engine and its required SDK. External MCP access can run without any of these engines. In shared mode the installer reuses compatible local tools and installs missing engine tools in the current user’s library. Go is downloaded only when compiling the native launcher.

Initial reuse policy: exact Node24.21.0, Codex0.146.1, Claude Code2.1.296, OpenCode1.19.0 and Go1.27.2. Other versions are retained; supported versions coexist. Finding a CLI does not log in or guarantee model access.

Windows: %LOCALAPPDATA%\Saplingagent\
macOS: ~/Library/Application Support/Saplingagent/
GNU/Linux: ~/.local/share/Saplingagent/
  runtimes/    verified program and SDK versions
  index/       published complete generations
  locks/       shared install ownership
  cache/       download cache

Each project retains its source, credentials, conversations, settings, data, logs and application dependencies. Tool aliases use symlinks or Windows junctions, with real-path bindings or a Node copy when unavailable. Machine PATH and original programs are retained.

Shared installations can reuse verified public npm tarballs. Each application keeps its own writable dependencies. For a deployed UI, add "frontendMode": "static" to config/runtime.json and restart the app to serve the built page through its gateway. The default development mode supports hot reload.

For headless GNU/Linux installation and Node reuse, see the Linux setup guide.

Install and repair

bash Saplingagent.sh

Later projects reuse installed versions. App launch checks dependencies; full restart also repairs missing tool references. Shared updates publish a new generation without overwriting running programs. Each App owns its processes and ports. No shared-library automatic deletion is implemented.

Run bash Saplingagent.sh doctor to inspect each selected tool's source, version and actual path without sending a model request.

Portable mode

SAPLING_RUNTIME_MODE=portable bash Saplingagent.sh install

This Bash command keeps the tool store inside the project and avoids external CLI reuse. Return to sharing with SAPLING_RUNTIME_MODE=shared during installation. A copied project repairs references on launch; missing dependencies require network access. Advanced override: set SAPLING_RUNTIME_HOME to an absolute directory before installation.

共享运行环境

安装器先准备 Node 和配置页。选择 Codex、Claude Code 或 OpenCode 时才准备对应的引擎及所需 SDK。只用外部 MCP 时无需安装这三个引擎。共享模式优先检测本机兼容工具，缺少适用的引擎工具时才下载到当前用户的共享目录。只复用程序，不会自动登录。Go 仅在编译启动器时准备。

新项目共用工具和 SDK；源码、配置、账号、会话、数据及应用依赖仍独立。共享程序按版本并存，安装有共享锁，不覆盖原来的系统程序。链接不可用时使用实际路径或复制 Node。可用上面的 portable 命令保持文件夹自包含。复制到其他电脑后会重新检测环境。

多个项目可以复用已验证的公开 npm 安装包。长期运行的应用可在 config/runtime.json 中设置 "frontendMode": "static"，重启应用后由网关提供已构建的页面；默认开发模式支持热更新。无桌面设备的 Node 安装和启动方式见 Linux 安装指南。实际下载内容以 release 提交和 delivery.json 为准。Windows 原生安装和 Junction 行为尚待真机验收。在 macOS 上，安装 Node 的进程退出后，系统会释放它持有的锁。等待的项目会重新检查共享库，复用已完成的下载。
