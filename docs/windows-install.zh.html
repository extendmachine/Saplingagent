Saplingagent Windows 安装与配置

内核 0.9.5：本文介绍当前源码的外部配置与轻量启动器流程；安装命令始终下载实际发布的 release 提交，main 的开发修改需要另行发布后才会分发。

安装与配置

Windows 10/11 Intel/AMD 64 位或 ARM64。首次运行请安装 Git for Windows 并使用 Git Bash；不是 WSL 路径。 Node、依赖和源码保存在项目内；不初始化 Git，也不删除客户已有 Git。

bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/extendmachine/Saplingagent/release/install.sh | bash -s -- --lang zh'

也可以解压完整源码，在其目录运行 bash Saplingagent.sh。

  1. 脚本检测设备并安装最小内核。项目内短进程 A 将配置包及独立 Node 复制到项目旁可见的同级临时目录（../sapling-config-*），启动外部配置 B 后退出。
  2. 网页填写名称、目标文件夹和图标，先保存项目设置；再保存自己的 Codex 账号或 Codex/OpenCode/Claude API 方案，可填写自定义 API 地址。凭据只保存在项目内；Claude 支持 API 凭据，不导入订阅登录。
  3. 完成修改后点击“保存并构建应用”。B 停止所属服务、等待退出，应用文件夹名称并在项目内编译启动器。配置页地址不变；不会覆盖已有目标目录。
  4. 等待构建完成，再点击“完成配置”。B 将临时目录交接给项目内 A，随后退出；A 等待 B 退出再清理临时包。
  5. 双击项目内 .app 或 .exe。启动器检查并安装缺少或变化的依赖，再打开应用；无变化时复用。Windows 日常打开 .exe 不依赖 Git Bash。

以后修改与恢复

运行 bash Saplingagent.sh configure 重新配置。每次修改后保存并构建，再完成配置；成功编译才替换旧产物。请将启动器与完整项目目录保存在一起。仅关闭浏览器标签不会结束配置。

浏览器未打开时，运行 bash Saplingagent.sh configure --no-open 并访问终端地址。缺少安装文件时用 bash Saplingagent.sh install --repair。构建失败后保留已保存配置及当前实际目录，修复后重试；被其他软件占用的文件应先释放。日志在 logs/project-launcher/。不要手动删除活跃配置的临时目录。

安装及编译可能联网下载锁定依赖和工具链；不发送模型提示。账号额度、有效期和接口兼容性需要自己的服务商验证。Windows 原生设备上的安装、文件占用、图标及重新编译仍需真机验收。
