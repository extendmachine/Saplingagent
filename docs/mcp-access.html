Connect an external AI through MCP

Use your own AI client to work on this project. The kernel supplies local file, shell, rules and Skills tools through MCP stdio. The external client supplies the model and conversation. A built-in Codex, Claude or OpenCode account is optional.

Set up the connection

  1. Run bash Saplingagent.sh and open the configuration page. Save the project name and folder settings.
  2. Choose External AI / MCP, enable access, and save. Select Use external AI only to finish setup without a built-in model account. This choice is independent of any saved provider scheme.
  3. Complete Save & build app. Wait for any folder rename and build to finish before exporting client configuration.
  4. Use Copy JSON or download the JSON. Add its mcpServers.saplingagent entry to a client supporting local stdio MCP. Clients with TOML or another format need the same command and args mapped to their own configuration fields. Saplingagent does not edit global client settings.
  5. Connect in the external AI client and ask it to read project_context and the project rules before work. The native tools can run with the application closed. Open the generated app when you need its preview and services.

The exported command uses the installed project-local Node and final project path, including spaces and Unicode. Copy a fresh configuration after moving or renaming the folder. The JSON contains paths, not AI keys. External conversations do not automatically appear in Saplingagent's chat history. The embedded chat still needs a built-in provider.

Permissions and tools

The tools have the current OS user's file and command permissions, matching the Full Access boundary of built-in Codex. Absolute paths, parent paths, symbolic links and explicitly requested work outside the project are supported. There is no Saplingagent path allowlist or additional operation approval; this does not grant root privileges. Your external AI client can still require its own approval. Project rules recommend working inside the project by default.

ToolsPurpose
workspace_list_files, workspace_read_fileInspect files and directories.
workspace_write_file, workspace_delete_file, workspace_run_commandModify files and run local commands. Reported results include actual failures; commands and edits are not automatically rolled back.
project_contextRead project guidance and status references.
skills_list, skills_readDiscover and read project-local Skills.

This independent kernel endpoint has eight tools. Existing application-owned MCP tools, preferences and page workflows remain separate. Use native file and shell tools for additional authorized work. The endpoint opens no network listener and uses no Saplingagent model account.

Disconnect before maintenance

Disconnect this project's MCP server in every external client before renaming the folder, replacing dependencies or updating/restoring the kernel. An active connection produces MCP_CLIENTS_ACTIVE before those changes. The client host is never terminated. Normal app restart and Quit manage app services; the independently connected MCP server remains controlled by its external client.

Disabling access rejects subsequent tool calls; stop any running command in the client and disconnect to finish shutdown. If the client crashed, inspect .runtime/mcp-access/clients/ before removing a stale receipt; do not erase live ownership records. For commands up to one hour, the client may need a tool timeout of at least 3615 seconds. Cancellation stops the MCP server's own command process group, not unrelated processes.

Storage and compatibility

Settings: config/mcp-access.json. Process receipts: .runtime/mcp-access/clients/. Metadata logs: logs/mcp-access/. No global or system-temporary configuration is written. Kernel source and its SDK dependency remain under kernel/; settings and customer Skills remain application-owned.

See the tool contract and deployment notes. MCP stdio semantics follow the official transport specification. The existing maintained SDK v1 line is pinned for compatibility. Native Windows and individual third-party clients require their own acceptance testing.
