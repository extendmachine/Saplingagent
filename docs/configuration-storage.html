Launcher guide · Overview

Configuration storage stays beside your project

Kernel 0.9.5 derives every Saplingagent-managed configuration destination from the actual project folder. Configuration runs in a short-lived sibling so it can rename the complete project without keeping its own executable open inside it.

parent-folder/
├── Your project/
│   ├── kernel/                 canonical management code
│   ├── kernel/.cache/         built configuration module
│   ├── .runtime/ and .cache/  local tools and temporary/cache output
│   ├── local-secrets/         credentials and private configuration
│   └── Your project.app      launcher output
└── sapling-config-…/          temporary configuration process B
    ├── code/ and ui/
    ├── node (or node.exe)
    └── tmp/ and cache data

The terminal displays the relative sibling path. Keep the configuration page open to inspect it in the parent folder. Finish setup hands control back to project process A, waits for B to exit, and removes only that verified sibling. Closing a browser tab alone does not request this handoff. Each project/session has independent ownership records; unrelated folders are never swept.

Saving and rebuilding

Finish editing project and AI settings, save, build the app, then finish setup and wait for completion. The application is a thin launcher for this complete folder. Configuration holds exclusive operation receipts while stopping owned services, renaming and compiling. Concurrent starts/install/update/builds refuse conflicting work. Native replacement stages new output; file locks produce a retryable error without erasing an unrelated or previous usable artifact.

Storage boundaries

Persistent configuration, credentials, dependencies and app output stay in the project. Helper paths are derived from its parent; there is no global temporary/home fallback. Managed temporary/cache/XDG destinations are rebound for child processes and for A after handoff. Existing symbolic links in managed output ancestors are refused before following them outside. Internal canonical absolute paths are used to verify ownership; they are not fixed external storage locations. Explicitly importing an existing account reads its original file without modifying it.

These are rules for Saplingagent's configuration implementation. Customer AI tools retain Full Access. Browser and operating-system internals are outside the managed-output guarantee.

Interrupted operations

Do not delete a live helper or unknown lock. Read the displayed error and project logs, close the program holding the file, then retry from the actual project folder. Never remove an unrelated session based only on its directory name. Old system-temp configuration sessions must finish through the old running process before installing this layout. No automatic rollback or customer Git reset is performed.
