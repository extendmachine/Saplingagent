Fresh install without Git

Download the release snapshot and run bash Saplingagent.sh. Choose Install / repair dependencies, Configure AI, then Start app. No Git metadata is shipped or initialized, no remote is connected and no storage question appears. Existing customer Git is preserved. You can set up your own Git separately.

Upgrade from the page

  1. Open Kernel at the top right, or open /__saplingagent/kernel directly.
  2. Check for kernel update. This pins the official release SHA and stages verified source without stopping the app.
  3. Review changed paths, preserved local edits and conflicts. Resolve conflicts deliberately; local core changes are not silently overwritten.
  4. Acknowledge the compatibility warning and click Upgrade kernel & restart. Wait for active tasks first.
  5. A separate loopback progress page takes over. It stops owned services, backs up and applies core, repairs only core dependencies, starts the complete app and redirects to its actual selected port.

Failures and explicit recovery

Source apply, dependency repair and app readiness are separate results. Authentication, network or custom service failures are not reported as successful upgrades. Keep the maintenance page open to retry dependencies/start or explicitly restore the saved source backup. Nothing automatically rolls back. Data and external actions are not restored with source.

Backup journals: .runtime/kernel/backups/; worker state: .runtime/kernel/jobs/; logs: logs/kernel-manager/ (daily,30days). A crashed worker leaves .runtime/kernel/active-job.json; verify its process has exited before manually clearing it. Never delete an active lock. Offline source recovery: node .runtime/kernel/recover.mjs BACKUP_UUID, followed by kernel dependency repair and startup. A backup that contains later core edits requires manual reconciliation.

Transition from0.9.1

Schema3 releases older Git controls and app dependency manifests. Both directions reject obsolete schemas before source writes to avoid deleting application files. Download0.9.2 into a new folder; keep the old folder and deliberately move your application, data and configuration. Do not regenerate a recipient baseline or blindly overwrite credentials. Compatible future schema3 releases support the web upgrade path.

Product release labels identify the initial complete distribution; installed kernel has its own version. A kernel update does not rewrite application-owned product metadata.
