Evolution through conversation

Read project goals/rules, inspect relevant files and evidence, implement the requested frontend/backend capability, run suitable checks and report actual results. seed-page-edit supports implementation, seed-research checks official evidence and seed-skill-author creates reusable workflows. Full Access does not add authorization beyond the user's request.

Direct file writes and commands are supported. Optional page_propose/page_apply records multi-file candidates without compulsory compile/hash gates. page_rollback restores recorded originals only on user request; snapshot failures are warnings and cannot be presented as guaranteed recovery.

Sessions and progress

Sessions are stored in data/workspace; Codex authentication/thread runtime uses local-secrets/codex. Missing-session recovery keeps retry input and does not silently resend it. Stop, shutdown and completion clear per-turn monitors. The last effective progress is tracked in memory without storing reasoning/tool bodies in progress metadata.

turnTimeoutMs defaults to 0; turnIdleWarningMs defaults to 600000. Explicit nonzero total deadlines still interrupt. File/command tools have independent resource/output/time bounds.

Run, stop and distribute

Use Saplingagent.sh on macOS or Saplingagent.sh on Windows x64 and ARM64. See the Windows guide. Developer entry points are node scripts/install.mjs, node scripts/login.mjs and node scripts/dev.mjs with the documented project-local environment. The Mac installer keeps authentication isolated; direct developer setup has separate existing-auth import behavior described in scripts/README.md.

Restart for backend/MCP/dependency changes. Logs are daily metadata files under logs/<service>/ with 30-day retention. Private files, data and logs are Git-ignored. Distribute the clean committed source package, not a copy of the running folder.

Automatic port selection

5173 is a starting port. If it or an internal service port is occupied, unified startup scans upward and selects distinct available loopback ports. Use the actual Web page URL printed in the terminal. Other applications keep running, and config/runtime.json is not rewritten. The selected URL stays the same during Restart app/backend; a new launcher scans again. Diagnostics uses this instance’s runtime-address metadata. If an internal bind races another process, relaunch to select again.

Complete project restart

POST /api/runtime/restart with optional {scope:"all"|"backend"}, default all, returns202 with jobId/status. Full restart reloads discovered Node backends and config/services.json project registrations, dependency order and readiness; the browser refreshes after completion without closing the launcher. GET /api/runtime/status includes optional project/port fields on services. No command, path or PID is accepted in the HTTP request.

Existing loopback Host/Origin and script Bearer controls remain. Invalid manifests,missing entries/cwd,dependency cycles and unavailable commands are rejected before stopping live services; startup failures keep recovery available. New errors: INVALID_SERVICES and FULL_RESTART_REQUIRED (choose Restart app rather than backend-only for internal port edits). Public/control addresses stay stable.
