Evolution through conversation

Read project goals/rules, inspect relevant files and evidence, implement the requested frontend/backend capability, run suitable checks and report actual results. seed-page-edit supports implementation, seed-research checks official evidence and seed-skill-author creates reusable workflows. Full Access does not add authorization beyond the user's request.

Direct file writes and commands are supported. Optional page_propose/page_apply records multi-file candidates without compulsory compile/hash gates. page_rollback restores recorded originals only on user request; snapshot failures are warnings and cannot be presented as guaranteed recovery.

Sessions and progress

Sessions are stored in data/workspace; Codex authentication/thread runtime uses local-secrets/codex. Missing-session recovery keeps retry input and does not silently resend it. Stop, shutdown and completion clear per-turn monitors. The last effective progress is tracked in memory without storing reasoning/tool bodies in progress metadata.

turnTimeoutMs defaults to 0; turnIdleWarningMs defaults to 600000. Explicit nonzero total deadlines still interrupt. File/command tools have independent resource/output/time bounds.

Run, stop and distribute

Use Saplingagent.sh on macOS or Saplingagent.sh on Windows x64 and ARM64. See the Windows guide. Developer entry points are node kernel/scripts/install.mjs, node kernel/scripts/login.mjs and node scripts/dev.mjs with the documented project-local environment. The Mac installer keeps authentication isolated; direct developer setup has separate existing-auth import behavior described in kernel/scripts/README.md.

Restart for backend/MCP/dependency changes. Logs are daily metadata files under logs/<service>/ with 30-day retention. Private files, data and logs are Git-ignored. Distribute the clean committed source package, not a copy of the running folder.

Automatic port selection

5173 is a starting port. If it or an internal service port is occupied, unified startup scans upward and selects distinct available loopback ports. Use the actual Web page URL printed in the terminal. Other applications keep running, and config/runtime.json is not rewritten. The selected URL stays the same during Restart app/backend; a new launcher scans again. Diagnostics uses this instance’s runtime-address metadata. If an internal bind races another process, relaunch to select again.

Complete project restart

POST /api/runtime/restart with optional {scope:"all"|"backend"}, default all, returns202 with jobId/status. Full restart reloads discovered Node backends and config/services.json project registrations, dependency order and readiness; the browser refreshes after completion without closing the launcher. GET /api/runtime/status includes optional project/port fields on services. No command, path or PID is accepted in the HTTP request.

Existing loopback Host/Origin and script Bearer controls remain. Invalid manifests,missing entries/cwd,dependency cycles and unavailable commands are rejected before stopping live services; startup failures keep recovery available. New errors: INVALID_SERVICES and FULL_RESTART_REQUIRED (choose Restart app rather than backend-only for internal port edits). Public/control addresses stay stable. Kernel baseline version

The bottom footer displays Kernel version 0.90 alongside the current Git version. This fixed source-owned value identifies the original kernel baseline, remains visible when Git is unavailable, and changes only with an explicit kernel release.

Collapsible AI chat

The AI conversation opens in a panel at the right edge. Use Collapse chat to free the application area, then the AI chat tab to reopen it. Drafts, messages and running replies stay active while collapsed. On smaller screens the open panel uses the available width. Kernel and Git versions remain in the bottom version bar.

Files, images and fresh page inspection

Use the chat paperclip for multiple files, drop files/images onto the conversation, or paste clipboard content that exposes image/file bytes. Normal text and copied filesystem paths remain text. Each file may be20MiB and each message10 attachments. Wait for upload completion; remove and select again after a failed upload. You may send attachments without text.

Sent attachments restore with the conversation. PNG/JPEG/GIF/WebP show previews; other files download and are referenced for native Agent file tools. Uploading does not automatically execute files or promise PDF/Office extraction. Actual image understanding depends on the selected model and provider. Removing a composer item does not erase its local original in data/attachments; unsent selections survive collapse but not a full page reload. Back up attachments with sessions.

After changing the interface, AI can use page_read to request fresh DOM/text, element bounds/styles and an optional DOM-rendered PNG from the open project page. Keep the page open and reload after updating. The default entry connects automatically, including when chat is collapsed; another standalone entry needs PageContextBridge. Existing project file reads require no additional folder permission. No OS screen-recording prompt or desktop capture is used.

Password/input values, drafts, chat messages and data-page-private regions are excluded. Unavailable pages, missing selectors, failed images and truncated captures are reported explicitly. DOM-rendered images can differ from native browser screenshots; external assets, cross-origin frames, canvas/video and fonts have limits. Source access does not by itself verify a rendered page. Restart app once to load changed backend/MCP code, using the existing project lifecycle. API details.

One complete-restart action

The main page provides only Restart app. Click it to stop the existing frontend and backend processes, including the managed project service plan, then start them again and wait for service, Agent and MCP readiness before the page refreshes. The public gateway and runtime controller remain available during this sequence. Busy work refuses restart; a failed startup reports the real error and does not claim completion. No backend-only dropdown or recovery link is shown beside the button. The diagnostic recovery address remains available through the gateway if the app cannot load.

Automatic ports during restart / 重启时自动顺延端口

Cold startup, Restart app and Restart backend check available internal ports. If another project takes an old port, this project selects a free one without stopping the other project. The browser URL stays the same. When endpoint changes require it, a backend restart also refreshes the frontend so its proxy uses the new address.

冷启动、重启应用和重启后端都会检查内部端口。旧端口被其他项目占用时，本项目自动选择可用端口，浏览器入口保持不变；后端端口变化时，会在同一次操作中刷新前端，确保代理指向新地址。不会关闭占用端口的其他项目。

Bind races retry up to eight times; readiness or authentication errors still need their own repair. To load this controller fix, stop this app normally and open it again once. No native rebuild is needed.

端口探测后又被占用时，最多进行八次启动尝试；登录或服务就绪错误仍需单独处理。现有运行实例需正常停止后重新打开一次，才能加载这项控制器修复，无需重新编译 App。

Configure AI from Settings / 从设置进入 AI 配置

Choose Settings → Configure AI. An independent AI settings page opens in the system browser. It only edits accounts, provider schemes, models and external MCP access. Opening the page keeps services running; save work before the first credential or scheme change, which pauses this project's services. Choose Finish & restart to close configuration, clean its temporary sibling folder and resume the existing app. Project name, folder, icon, conversations and compiled launcher stay in place. No app rebuild is required.

从主页面右上角点击设置 → 配置 AI，进入独立的 AI 设置页。这里只修改账号、服务商方案、模型和 MCP 接入。打开页面不会停服；首次更改账号或方案前请先保存工作，服务随后暂停。保存后点击完成并重启，清理临时配置进程并启动现有应用。项目名称、目录、图标、会话和已编译 App 保留，无需重新构建。

Fallback / 备用入口：bash Saplingagent.sh configure --ai-only。bash Saplingagent.sh configure retains full project setup / 仍用于完整项目配置。If another setup mode is open, finish it first; the launcher does not switch an unsaved session. 若另一种配置页面仍在运行，请先结束该页面。If browser opening fails, paste the displayed local address into a new tab.
