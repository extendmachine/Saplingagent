Configure outside the project. Launch from your folder.

Kernel 0.9.5. Keep the complete project folder; the small app is its bootstrap.

  1. Run bash Saplingagent.sh in macOS Terminal or Windows Git Bash. It detects the device, installs the local minimal kernel and opens the configuration page.
  2. The original entry A copies the small configuration backend, built webpage and Node runtime into a private external temporary folder. Configuration B starts there; A and the installer exit.
  3. Save the project name, folder and optional icon, then save your AI account/API scheme. Configuration does not send a model prompt.
  4. Choose Save & build app. B closes owned sign-in processes, stops this project's idle services, waits for the original launcher to exit, applies the folder name and builds the named .app/.exe in the final project. The same page shows progress. Existing destinations are never replaced.
  5. After success, choose Finish setup. B starts A at the final project path, waits for acknowledgement and exits. A waits for B to release its executable, deletes only that verified temporary folder and exits.
  6. Double-click the app. It checks Node and declared dependencies, installs missing or changed groups locally, then opens the project status page at the actual runtime URL. Choose Open app to enter the application. Normal activation does not copy B or reopen configuration.

macOS Dock lifecycle

The generated .app remains in the Dock while the existing project services run. Click its icon to reopen project status without creating another service cluster. Quit or Command-Q cancels pending startup, stops only this project’s services and exits after shutdown. Closing the browser alone does not stop services. A failed shutdown keeps the Dock app open and reports the failure; inspect logs/project-launcher/ and retry.

Configuration closes the native app through its owned handoff and waits for the app and helper to exit before moving the folder or replacing the launcher. Existing exported apps need one explicit Save & build app after updating the source to adopt Dock behavior. Normal browser controls, registered services and Agent Full Access stay unchanged. Force Quit or an OS crash can bypass normal shutdown; reopen the app and use normal Quit to request cleanup.

Reconfigure and rebuild

bash Saplingagent.sh configure
bash Saplingagent.sh configure --no-open
bash Saplingagent.sh install --repair

Reopen configuration to edit the name/icon/AI scheme or rebuild. New output is checked in same-volume staging before replacing the old launcher. Unchanged native source/name/icon reuses the existing executable. Business backend changes use Restart app. Separate folders select independent free ports. Only verified owned processes are stopped; active tasks refuse destructive operations.

When an operation fails

On macOS, an older Dock bridge can report DOCK_OWNER_INVALID for a folder containing Chinese or other Unicode characters when launched from Finder. The corrected bridge reads process identity using a UTF-8 subprocess locale; it does not require renaming the folder or changing system language settings. Existing Dock apps use the corrected bridge without recompilation for this fix alone. Other startup failures still require the specific error in the launcher log.

The actual current project and saved settings remain available. Read the displayed error and logs/project-launcher before retrying. A directory lock from an editor, terminal, antivirus or sync program may still refuse a rename. There is no automatic rollback or deletion of customer Git/data. An interrupted setup lease or unknown temporary session needs inspection; do not delete unrelated temporary folders. Completed cleanup is recorded only after the external directory was removed.

App dependency downloads need network access and preserve the project-local environment. Windows daily activation can repair Node through the shared PowerShell helper without Git Bash. Initial script installation still requires Bash. Targets are macOS Intel/Apple Silicon and Windows10/11 x64/ARM64. Cross-compilation is not Windows hardware acceptance. Local Mac ad-hoc signing is not commercial notarization. Model access and quota need the user's own account and separate validation.

Project-relative configuration storage

Temporary configuration runs in a session-owned ../sapling-config-… directory beside this project. The terminal prints its location; Finish setup waits for exit before cleanup. Persistent settings, caches and outputs remain local. Directory layout and process locks.

Project status on activation

Open the compiled app to see startup progress and the runtime status page. Review the actual service ports, open the application, restart, stop owned services or open the local logs folder. Closing a display does not stop the backend. See the project status guide. Existing native launchers need an explicit rebuild for the progress display.
