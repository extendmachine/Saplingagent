Kernel management

Old numbers → Kernel0.9.5

There is one current Saplingagent version: Kernel0.9.5. Historical0.90/0.91/0.92 were written in a different numeric style. Their shipped comparator sees0.9.4 as older, so its Check update cannot repair itself. The new updater recognizes these labels without changing your original baseline. This is not permission to overwrite local edits.

  1. Stop this application through its launcher. Retain business-data backups in addition to source backups.
  2. In Terminal or Windows Git Bash, enter the existing application's folder. Download fresh tooling into its ignored .cache directory; use a new folder name if it already exists.
bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/extendmachine/Saplingagent/release/install.sh | bash -s -- --download-only --dir "./.cache/kernel-version-tooling-0.9.5"'

Use the existing project-local Node executable. The following Bash selection covers the installer-created macOS and Windows layouts. It installs nothing globally.

SAPLING_NODE=''
for candidate in .runtime/node-*/bin/node .runtime/node-*/node.exe; do
  if [ -x "$candidate" ]; then SAPLING_NODE="$candidate"; break; fi
done
if [ -z "$SAPLING_NODE" ]; then printf '%s\n' 'Project-local Node is missing; repair the local installation first.'; else
  "$SAPLING_NODE" .cache/kernel-version-tooling-0.9.5/kernel/cli.mjs --root . check
fi

This explicit target is your original app, not the temporary tooling folder. Check is preview only. If it reports conflicts, merge them deliberately; do not erase the baseline or overwrite your application with downloaded source. Do not continue while the app is running. When the preview is acceptable, run the explicit update and answer its existing risk prompt:

"$SAPLING_NODE" .cache/kernel-version-tooling-0.9.5/kernel/cli.mjs --root . update

The updater verifies official immutable source, stops at conflicts/live targets, saves an owned-source backup and applies only declared kernel files. Then use the original app's Saplingagent.sh install --repair and start/recheck it. The UI should read Kernel0.9.5 from its installed manifest. Credentials, app source/config/data and Git remain local. Repair/source readiness does not certify model access. Recovery remains explicit through the saved .runtime/kernel/recover.mjs helper; a source restore does not restore business data. Real customer customizations may still prevent migration; reconcile them before applying.

On an already unified version, ordinary in-page updates remain available. Temporary tooling can stay under .cache; it is not your working application or a sibling developer dependency.
