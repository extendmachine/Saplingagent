Saplingagent macOS 安装与接口配置

一行命令安装 release

在 macOS 终端或 Windows Git Bash 的目标上级目录运行下方命令。Windows 先安装 Git for Windows。引导脚本只下载 release 的固定提交到新建 Saplingagent 文件夹，再自动安装并打开现有菜单；随后配置自己的 AI 接口并启动。

bash -o pipefail -c 'curl -fsSL https://raw.githubusercontent.com/extendmachine/Saplingagent/release/install.sh | bash -s -- --lang zh'

可传 --dir 指定新文件夹，--download-only 仅下载。已有目标目录不会覆盖。首次安装初始化客户目标和任务记录，安装前已有修改会保留。跟随模式后续普通 fetch 也只拉选中的 release、不拉标签，不自动带入作者 main/testcode。仅本地模式的 main 是客户自己的独立历史。公开仓库仍可主动访问；AI 全部权限不变。

这是首次安装方案，不是现有源码更新器。安装后可在应用目录执行 bash Saplingagent.sh。完整说明

使用一个 Saplingagent.sh 脚本完成安装、配置接口、启动和诊断。中文和英文共用同一个脚本，完整应用文件夹必须一起保留。

运行要求

macOS 13.5 或更新版本，Apple Silicon 或 Intel，可写的本地文件夹，以及可连接 Node.js、npm、OpenAI 和所选模型服务商的网络。压缩包安装不要求全局 Node、Homebrew、Xcode 或 Codex 桌面应用；版本管理和重新打包需要 Git。自动化检查在 Apple Silicon 上执行，Intel 的真实安装仍需相应设备验证。

模型调用使用你自己的账号或 API，实际模型权限、额度和费用由对应服务商决定。安装或登录成功不等于模型调用一定可用。

如何运行 .sh 脚本

解压完整应用，在“终端”中进入应用文件夹。输入 cd ，把应用文件夹拖入终端，按回车；然后运行：

bash Saplingagent.sh

先选择 1. English 或 2. 中文；直接回车使用英文。也可直接打开中文菜单：

bash Saplingagent.sh --lang zh

Mac 可以运行 .sh。Finder 双击通常会用编辑器打开脚本，请按上述方式在终端运行。使用 bash 不需要额外执行 chmod。文件有可执行权限时，也可以运行 ./Saplingagent.sh。此脚本使用 Bash 语法，请不要改用 sh Saplingagent.sh。

配置账号与 API

Codex：选择“配置 AI 接口 → Codex”，官方工具将打开浏览器，使用自己的 ChatGPT / Codex 账号登录。项目凭据保存在 local-secrets/codex/，不导入开发者账号。目前此 Mac 入口没有独立的 Codex API-key 登录向导。

OpenCode：选择“配置 AI 接口 → OpenCode”，按官方工具提示选择服务商并配置密钥或登录。凭据和配置位于 local-secrets/opencode/。自定义 API 地址及模型需要按现有 OpenCode 服务商文档配置；这个菜单不提供新的自定义地址向导。

启动使用网页中保存的默认账号或 API 方案。选择 OpenCode 时无需另行登录 Codex；已有对话保留原有引擎。

正常安装、登录和启动已接入 Codex App Server；无需在 Codex 桌面应用中手动添加 MCP。项目使用 codex app-server --listen stdio:// 和本地 MCP / Skills，模型由你的账号提供。

问题处理与分发

提示 Node 未安装或依赖变化时，运行 bash Saplingagent.sh --lang zh install --repair。认证失败请查看实际账号错误；重新安装不能增加模型额度。端口被占用时停止自己的旧启动终端或修改配置，脚本不会按端口强行终止其他项目。服务未就绪时使用“服务诊断”及运行恢复页 /__saplingagent/runtime。

安装锁存在时先等待，确认安装进程已结束后再按英文安装说明清理当前项目内的旧锁。移动应用前停止服务并移动整个文件夹；架构或锁文件变化后重新安装。

项目权限沿用当前系统用户的 Full Access，不自动提升为 root。源码采用 PolyForm Noncommercial 1.0.0，商用需要项目方另行许可；第三方认证权益需要独立确认。本安装包不是签名的原生 Mac 应用。分发请使用干净源码包，排除自己的凭据、聊天数据、日志和已安装运行环境。

文件夹边界与对话回执

分发时，全部项目自有代码、rules、MCP、Skills、配置、文档和脚本都在完整应用文件夹中。开发 Saplingagent 不修改文件夹外的代码，也不依赖开发者的其他项目；模型服务和安装时下载的依赖仍是声明的外部要求。

客户 Agent 保留当前系统用户的 Full Access。rules 默认建议在本文件夹内修改，客户明确要求时可以修改外部代码，不增加路径白名单或权限拦截。每次最终回复，包括只读对话，都要求给出同样的八项完成复核回执；只读对话不因此创建任务记录。实际模型是否遵循格式仍需真实对话验证。

独立的 AI 配置网页

安装后选择「配置 AI 接口」，脚本会打开当前项目专用的本地配置网页。ChatGPT 账号页签提供官方浏览器登录或设备码；API 页签支持命名方案、自选服务商 API Base URL、API 协议、密钥和准确模型 ID。Codex 自定义接口采用 Responses，OpenCode 可用 Chat Completions、Responses 或 Anthropic Messages。多个方案可以保存并切换默认值。

编辑已有方案时密钥留空会保留；读取模型列表是可选操作，不会发送对话。点击「完成配置」关闭配置服务并返回菜单，然后启动应用。网页关闭按钮本身不会停止服务。已运行的应用需要重启，并新建对话使用新的默认方案。默认 OpenCode 或自定义 Codex API 无需先登录 ChatGPT。密钥保存在项目内 local-secrets/api-keys，方案在 local-secrets/ai-config，不导入全局账号。

bash Saplingagent.sh --lang zh configure
bash Saplingagent.sh --lang zh configure --no-open

自动打开失败时使用终端打印的本地网址。详细说明见 AI configuration guide（英文）。真实账号登录、额度、模型工具调用和 Windows 真机流程需实际验收。

首次安装选择 Git 存放方式

客户默认下载 release 分支。安装时选择：仅本地（有本地 Git 历史，无远端）、自己的仓库（输入已创建的仓库地址，作为 origin）、跟随作者 release（upstream）。Git 子菜单仅有 1、2、3，必须明确输入选项编号，回车不会触发清除。选 1 前显示提示，清除现有 Git 提交历史、分支、标签、版本名称、暂存索引和远端配置，重建只有 main 的空仓库、0 条提交、无云端链接。应用文件、未提交内容、数据和凭据保留。页面显示 main / No commits yet，之后主动点击 Save version 才产生第一条记录。重装保留已保存的选择和后续历史；再次明确选择仅本地则重新清除。选 2 会将 origin 新建或更新为用户填写的远端地址，保留其他非作者远端。下载源码默认 release；仅本地初始化固定为空 main，自有 / 跟随模式可配置分支。

先停止应用，再选择菜单 5「Git / 存放配置」，或运行 bash Saplingagent.sh --lang zh git 修改选择。配置保存在本地 .git/config，重装 / 修复保留当前选择。安装不会自动 pull、push、创建远端仓库或提交 PR，选 1 清除全部 Git 元数据，选 2 按用户填写的地址更新 origin；源码和未提交文件内容保留。Git 子菜单移除 4 和 0，主菜单的诊断和退出仍保留。旧版已保存的保留现有配置仍兼容重装。源码安装包不带 .git，用户选择后初始化；Mac 缺少 Git 时需安装 Apple 命令行工具（xcode-select --install），Windows 的 Git Bash 提供 Git。

跟随模式只获取上游历史，保留分发目录并基于实际源码提交建立本地快照。没有清单的 ZIP 必须与上游某个提交一致；无法识别或已修改的 ZIP 可选本地 / 自有仓库，或使用 Git 克隆。之后先执行 git fetch upstream 查看变更，再自行合并 git merge upstream/release，解决冲突、复核本地目标和任务记录后重启。选择安装 / 更新时，跟随上游模式会检查并合并可兼容的源码；本地／自有仓库只检查依赖并保留客户代码。分叉历史上的 pull 会停止，不会强制覆盖。

自动安装可设置 SAPLING_GIT_MODE=local、own 或 upstream；own 需要 SAPLING_GIT_REMOTE，可用 SAPLING_GIT_BRANCH 自选初始分支。网址不应包含密码或 token。Full Access 不变。

菜单 1：安装与更新

输入 1 并回车后立即显示启动信息，并分别报告源码和依赖结果。跟随 release 的目录会检查已配置的上游分支，保留本地提交并合并兼容源码；源码变化后重新加载启动器和运行环境配置，再检查依赖。本地／自有仓库仅检查依赖，不覆盖自行开发的代码。独立存放模式不再显示跟随上游选项；确需重新接入时使用下方明确的配置命令。

请先在运行应用的终端按 Control+C 停止服务，并保存未提交修改。未保存文件、运行中的端口、合并冲突、无共同历史或 Git 版本过旧会暂停源码更新并说明原因。自动合并需 Git 2.38+；冲突预检查不改变工作文件。历史／非跟踪版本保留；install --repair 只修复依赖。没有强制重置、自动回退、推送或 PR。

旧版本的菜单 1 仍只检查依赖，需要先按原有手动方式更新源码：git fetch upstream，然后 git merge upstream/release；如有冲突先处理并复核。再次运行本目录 Saplingagent.sh。curl 安装入口仅用于新文件夹，不要覆盖现有客户目录。

独立存放后的菜单

保存「仅本地」或「自己的仓库」后，再次打开启动器不显示 1. 安装 / 更新；Git / 存放配置只显示 1 仅本地和 2 自己的仓库，不再显示跟随作者 release。配置 AI 接口、启动应用、服务诊断、Git 配置、语言切换和退出仍可用。首次安装和跟随模式仍显示三个存放选项。每次操作后重新读取本目录保存的配置；显示菜单不会改动 Git 历史或远端。

依赖缺失或变化时运行 bash Saplingagent.sh --lang zh install --repair，只修复本地依赖，保留独立源码和 Git 配置，不获取上游源码。显式 install 命令仍可用。确实需要重新接入作者 release 时，先保存修改并停止服务，再明确运行 SAPLING_GIT_MODE=upstream SAPLING_GIT_BRANCH=release bash Saplingagent.sh --lang zh git；历史或分支冲突需要自行处理。菜单变化不限制 AI 权限。

自动顺延端口

5173 是起始端口。网页或内部服务端口被占用时，统一启动器向后顺延，选择互不重复的可用本地端口。请使用终端打印的实际网页地址。其他应用保持运行，不改写 config/runtime.json。本次启动的地址在重启前后端时保持不变；重新运行启动器才重新分配。服务诊断读取当前实例的实际地址。内部端口若在绑定前被其他进程抢占，请重新启动分配。
