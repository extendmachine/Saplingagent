TASK-20261010-006进展监测：活动轮session可带可选progress对象，含startedAt、lastProgressAt（ISO时间）、lastProgressKind（started/text/reasoning/plan/command-output/file-output/mcp-progress/item-started/item-completed）、idle（布尔）和phase（working/tool-running/waiting-user）。元数据仅在Agent内存中，结束省略，不修改workspace存储或返回推理/工具原文。默认turnTimeoutMs=0（缺字段同样0）关闭整轮硬时限；turnIdleWarningMs=600000在连续10分钟没有有效进展时通过既有status.label提醒，仍running，无error/done，不自动停止或重发。每段闲置提醒一次，新进展继续；GET /api/events及相同请求重连补发当前提醒。非空文本/推理/计划、不同的有效计划更新、有效item开始/结束、命令输出和MCP progress.message更新进展，心跳/HTTP轮询/重连/保存/错误重试不续期，旧thread/turn不能续期或结束新轮。静默工具提示仍在运行；标准Full Access确认继续自动允许，未新增自由问题界面。显式正总时限仍真实中断，两个配置均只接受0至2147483647整数毫秒，0关闭对应计时器。详见任务交接。

会话恢复修复候选（TASK-20261010-003）：所选会话请求返回404、NOT_FOUND且message为“Session does not exist”时，前端解除匹配的旧会话指针；专属SESSION_NOT_FOUND同样适用。列表、路由/裸404和网络、超时、401、500/503不清指针。保留原输入与requestId，用户点击重试才发送，不自动发起模型请求；旧异步响应不覆盖新会话，其他标签的新缓存不被清除。接口字段不变，候选测试与同步状态见交接记录。

内部 HTTP

workspace契约：GET/POST sessions、GET/PATCH sessions/:id、GET/POST preferences、DELETE preferences/:id；GET health开放。原子JSON存储、显式证据、单进程队列。

app-builder契约：GET files/file/changes；POST files/write与files/delete直接操作文件并尽力记录原件；快照失败不阻止操作，以warnings和changeId为准；POST commands {command,cwd?,timeoutMs?}返回真实exitCode/stdout/stderr/timedOut/cancelled。POST changes返回ready候选、不强制验证；apply直接应用；rollback仅用户主动覆盖恢复，不拦截后续修改。允许所有当前OS用户可访问路径，绝对/相对和符号链接均可用。
