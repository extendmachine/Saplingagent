Conversation and launcher recovery

These changes belong to main development, kernel0.9.9. Their source commit identifies the exact code; an existing public tag does not include later main changes automatically.

SituationMeaning and action
Restore failedThe current view releases its running indicator and keeps its conversation ID. Check service status and retry explicitly; requests are never sent again automatically.
SESSION_TOO_LARGE / SESSION_SAVE_REJECTEDThe response body was rejected. The app attempts to save the true request result and release the conversation. Copy visible unsaved output before leaving or refreshing; then start a new conversation or inspect storage. A completed request ID does not execute again on retry.
SESSION_SAVE_FAILEDFinal state could not be confirmed. Keep this page open, check disk space and folder access, then retry. The app keeps recovery state and may refuse switching/restart until the result is saved.
STOP_UNCONFIRMEDThis turn may still be executing tools or editing files. Wait or choose Stop again. It remains reserved until the engine confirms completion; other Codex conversations are not closed. Closing a browser tab does not stop work.
Project status unavailable or shutdown incompleteAllow the launcher to check again. A lost connection can leave services running. After a partial shutdown, check the remaining service names in project status and retry Stop or Dock Quit. See logs/project-launcher/ if it persists.
REQUEST_HISTORY_EXPIREDThe original message still exists, but its retry record has expired. Its previous answer stays in the conversation. Send a new message if you want a new run.
Missing history entryInvalid or corrupt individual session files are omitted from the list without deletion. Back up data/workspace before manual recovery. System disk/access errors still produce errors.
GIT_LABEL_BUSYVersion naming retains live and unknown ownership locks. A proven dead owner is recovered with identity checks. Inspect legacy/unknown locks before removing them; age alone does not prove abandonment.

Chat response headers may take up to120seconds; ordinary requests use10seconds. These transport limits are not model turn deadlines. Existing request IDs support recovery when the browser loses a connection.

Transient compilation output is cleaned after failure. Failed publication may retain staged output for recovery. Shared Node/tool generations are kept because other projects can use them; do not delete the shared library as a general cleanup step. A setup helper is removed only when its identity and exit are verified. Inspect logs/project-launcher if shutdown fails.

Deploy matching frontend, Agent and Workspace changes together. A kernel-only update preserves application-owned chat and storage code, so it cannot install every conversation fix in a customized app. Keep customer data and source backups.

会话与启动器异常恢复

这些修改属于 main 开发版，内核版本保持0.9.9。准确代码由提交号区分；既有公开标签不会自动包含之后的 main 修改。

  • 恢复失败：当前页面会解除“运行中”显示并保留会话。先检查服务状态，再明确重试；不会自动重发消息。
  • SESSION_TOO_LARGE / SESSION_SAVE_REJECTED：正文被拒绝保存。系统会尝试保存真实请求结果并释放会话；请在离开或刷新前复制可见的未保存内容，再新建对话或检查存储。已完成的请求不会因重试而再次执行。
  • SESSION_SAVE_FAILED：最终保存状态尚未确认。保留页面，检查磁盘空间和文件夹权限后重试；恢复记录会保留，切换或重启可能暂时被拒绝。
  • STOP_UNCONFIRMED：本轮可能仍在调用工具或修改文件。继续等待或再次停止；在引擎确认前保留占用，不关闭其他 Codex 对话。关闭浏览器标签不会停止后台。
  • 项目状态无法确认或退出未完成时，请等待启动器重新检查。连接中断后服务可能仍在运行。如果只有部分服务退出，请在项目状态页查看剩余服务，再次选择「停止」或从 Dock 退出。持续失败时请查看 logs/project-launcher/。
  • 会话列表：逐个跳过损坏、非法或符号链接文件，不删除原件。手动恢复前备份 data/workspace；真实磁盘和权限错误仍会报告。
  • GIT_LABEL_BUSY：只自动回收已证实进程死亡且身份一致的命名锁。活进程、旧格式和未知归属的锁保留供检查，不能仅凭时间删除。

聊天等待响应头的上限为120秒，其他请求10秒，不是整轮模型运行时限。编译失败会清理临时阶段；发布失败可能保留产物供恢复。共享 Node/工具版本可能被其他项目使用，不自动清除。配置助手只有在身份与退出均可确认时才删除；关闭失败请检查 logs/project-launcher。

前端、Agent 和 Workspace 需要配套部署。仅升级内核会保留客户自有的聊天与存储代码，因此不会自动带入所有对话修复；请保留客户源码和数据备份。

出现 REQUEST_HISTORY_EXPIRED 表示原消息还在会话中，但可安全重试的记录已经过期。原回复保留；如需再次执行，可发送一条新消息。遇到 SESSION_TOO_LARGE 时，请在刷新或离开前复制页面上还没保存的回复。
