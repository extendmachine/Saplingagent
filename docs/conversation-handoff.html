Change AI, keep the conversation

An existing conversation can continue with Codex, Claude Agent or OpenCode. Its title, messages and attachments remain in one local conversation.

How to switch

  1. Wait for the current response to finish, or stop it and wait until it is saved.
  2. Choose an available AI. For Claude or OpenCode, choose its provider and model. For a Codex account, choose a model from its catalog; Refresh models asks App Server for the latest complete catalog. Codex API schemes keep their configured model.
  3. Apply the change. Your unsent draft and attachments remain in the composer.
  4. Send your next message. The newly selected AI receives prior conversation context at this point.

Switching alone does not send a model request. No other conversations are merged. Changing only the Codex model preserves its native thread as well as the visible conversation. Switching engines, including returning to an earlier engine, starts a fresh native session with the same visible history.

What is handed over

The Agent sends a role-labelled recent transcript excerpt, including incomplete-response status and available attachment references. The excerpt is bounded to 24,000 characters; omitted content is disclosed and the complete project-local session file is referenced for further reading. Historical text is quoted data; your latest message controls the requested actions.

Only visible saved conversation content is transferred. Hidden reasoning, global AI histories and credentials are not imported. Context/token usage becomes unknown when the model changes until the provider reports a new reading. Switching engines creates a new native session; changing only the Codex model keeps the existing thread. Transfer does not guarantee that a model will recall every detail or read every referenced file.

Requested and server-confirmed model

The model picker changes this conversation, not other conversations or global Codex settings. New messages use the saved choice after Apply. Legacy conversations can continue using the explicitly labelled project default. A missing explicit model remains visible as unavailable; choose an available model instead of silently falling back.

The separate model status shows the most recent model reported by App Server for this conversation. Until a report arrives, it stays unknown. A service-side reroute updates that report and may differ from the requested model. Catalog discovery and a server-confirmed model do not prove quota, billing or successful inference.

If catalog refresh fails, the page reports the failure and retains your selection and draft. Retry Refresh models after restoring the connection. If the configured startup preference is absent from the catalog, the default substitution is disclosed. Model availability depends on the installed Codex client and your account/workspace.

Failure and recovery

An unavailable AI or failed switch keeps your saved conversation. If the network disconnects after saving, reload to see the authoritative selection. Another browser tab changing the AI can make an older send stale; reload before continuing.

History remains pending until a successful response is saved. Failed or stopped attempts can receive the same handoff again on manual retry. No automatic retry or rollback occurs, and an interrupted response does not undo tool side effects.

Deployment

This feature belongs to the application’s backend/workspace/, backend/agent-runtime/ and front/chat/. Deploy these together and Restart app. The kernel version remains 0.9.8. Deploy the matching kernel model contract together with the application services and frontend; a kernel-only update does not install application chat changes.

Existing conversations require no bulk migration. Preserve data/ and credentials. Older application source may not preserve new session metadata on writes, so retain a data backup and a matching application source version before rollback.
