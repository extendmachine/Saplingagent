Change AI, keep the conversation

An existing conversation can continue with Codex, Claude Agent or OpenCode. Its title, messages and attachments remain in one local conversation.

How to switch

  1. Wait for the current response to finish, or stop it and wait until it is saved.
  2. Choose an available AI. For Claude or OpenCode, choose its provider and model. Codex uses the project’s configured model.
  3. Apply the change. Your unsent draft and attachments remain in the composer.
  4. Send your next message. The newly selected AI receives prior conversation context at this point.

Switching alone does not send a model request. No other conversations are merged. Returning to an earlier AI starts a fresh native session with the same visible conversation history.

What is handed over

The Agent sends a role-labelled recent transcript excerpt, including incomplete-response status and available attachment references. The excerpt is bounded to 24,000 characters; omitted content is disclosed and the complete project-local session file is referenced for further reading. Historical text is quoted data; your latest message controls the requested actions.

Only visible saved conversation content is transferred. Hidden reasoning, global AI histories and credentials are not imported. Context/token usage resets because a new native session begins. Transfer does not guarantee that a model will recall every detail or read every referenced file.

Failure and recovery

An unavailable AI or failed switch keeps your saved conversation. If the network disconnects after saving, reload to see the authoritative selection. Another browser tab changing the AI can make an older send stale; reload before continuing.

History remains pending until a successful response is saved. Failed or stopped attempts can receive the same handoff again on manual retry. No automatic retry or rollback occurs, and an interrupted response does not undo tool side effects.

Deployment

This feature belongs to the application’s backend/workspace/, backend/agent-runtime/ and front/chat/. Deploy these together and Restart app. The kernel version remains 0.9.6; a kernel-only update does not install application chat changes.

Existing conversations require no bulk migration. Preserve data/ and credentials. Older application source may not preserve new session metadata on writes, so retain a data backup and a matching application source version before rollback.
