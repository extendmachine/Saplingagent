Install Saplingagent on Windows

Windows 10 / 11 x64 and ARM64

Install Git for Windows to obtain Git Bash. Use a fully updated Windows 10 version1809+ Intel/AMD64 computer (19045 recommended), PowerShell 5.1 or later, a writable local folder and internet access to nodejs.org, npm and your model provider. Windows 11 x64 and ARM64 is also a target. The installer automatically selects native x64 or ARM64, even from an emulated terminal. 32-bit Windows is unsupported. Native Windows acceptance is pending; the development host is macOS.

One menu

  1. Extract the complete source folder. Do not run inside the ZIP.
  2. Open Git Bash in that folder.
  3. Run the command below and select English or Chinese.
  4. Choose Install / update, Configure AI → local account/API setup page, then Start app.
bash Saplingagent.sh

For Chinese add --lang zh. OpenCode provider/API configuration is available under Configure AI. Startup uses the saved default account/API scheme; OpenCode-only or custom Codex API access needs no ChatGPT login. Keep the launch window open; Control+C stops the owned services. Open the printed http://127.0.0.1:5173/ address if the browser does not open.

Local installation and authentication

The menu downloads official checksum-verified Node24.21.0 into .runtime/, pinned Codex0.146.1 and locked dependencies into this folder. Codex connects directly to its native App Server through stdio. Git Bash from Git for Windows is required. No global Node/Codex, WSL, registry/PATH changes or Codex desktop app are required. Windows system tools are called internally by the Bash helper; no standalone .ps1 entry or user execution-policy command is required.

Use your own model account. Account credentials stay in local-secrets/codex/; web API schemes and keys stay in local-secrets/ai-config/ and local-secrets/api-keys/. Legacy OpenCode selector credentials stay in local-secrets/opencode/. Authentication does not guarantee model entitlement or quota; fees follow your account/provider. The same Full Access applies as the current OS user; no root elevation or new directory restrictions.

Versions and restart

Windows installation requires Git for Windows to supply Bash. First installation creates local Git history after the storage choice. Fresh customer folders start release unless explicitly configured. Branch switching lists only actual available local branches. Select a version then Restart app; Restart backend keeps the frontend. The persistent recovery page is /__saplingagent/runtime. Finish active work first. Windows uses owned PID-tree termination, which is abrupt and cannot undo command side effects. Forced parent death and separately detached programs are outside guaranteed cleanup.

Troubleshooting and testing

Choose Diagnostics or use doctor. Repair dependencies with install --repair; device login with login --device-auth; start without browser with start --no-open. Stop before repairing or moving the folder. Remove a stale .runtime/windows-node.lock or windows-install.lock only after confirming no installer is running. Short local paths help avoid Windows path-length constraints.

On your Windows10 machine: install, sign in, send/stop a message, refresh, configure OpenCode, check MCP file edits in a disposable app file, and restart backend/app after source/version changes. Actual Windows login/model calls are not covered by current Mac tests.

Independent AI setup page

After installation, Configure AI opens a separate project-local web page. Choose ChatGPT account sign-in/device code, or a named API scheme with your own API Base URL, key, protocol and model. Keep multiple schemes and select a default; leave a saved key blank to retain it. Optional model discovery sends a catalog GET only.

Finish setup closes only this service and returns to the menu; then Start app. Closing the browser tab alone leaves setup running. Reconfigure an existing app, restart and create a new conversation. An OpenCode-only or custom Codex API scheme does not require ChatGPT login. Credentials stay in local-secrets and are not imported from global accounts.

Use the printed loopback URL if browser opening fails. See the step-by-step AI configuration guide. Actual OAuth, provider inference/tool calls and native Windows browser flow remain recipient validation.

First-install Git storage

Customer downloads and source packaging default to release. Installation asks for: local-only Git history (no remote), your own existing repository URL (origin), or following the author release (upstream). There are only three choices: 1 Local only (Enter default), 2 My own remote, and 3 Follow author release. Choice 1 initializes local Git if absent, or removes ALL remote links from an existing repository. Local files, staged changes, commits and the selected branch/version are preserved. Local snapshots and undo remain available. Choice 2 explicitly adds or updates origin to your supplied URL. A new ZIP starts real release history unless explicitly configured.

Menu 5, Git / storage setup, or bash Saplingagent.sh git changes the choice. Stop the running application first. The saved choice lives in local .git/config; reinstall/repair preserves your selected branch/version. A linked development worktree retains its shared configuration. No global Git settings, automatic pull/push, hosted repository creation or PR. Choice 1 removes custom origin/upstream/mirror links too. Choice 2 retains unrelated non-author remotes. An explicit branch setting can select another branch; pending changes must be saved before switching. Storage submenu choices 4 and 0 are removed; the main menu still offers Diagnostics and Quit. Older saved keep-existing configurations remain valid on reinstall.

Create your own remote repository first and enter an HTTPS/SSH URL without tokens/passwords. Follow mode fetches author history and anchors the delivered source to its recorded commit; raw ZIPs must match upstream history. An unidentifiable/edited ZIP can use local/own storage or a Git clone. Fetch failure can be retried. Install / update updates dependencies, not source; review git fetch upstream and explicitly merge reviewed changes with git merge upstream/release. Resolve conflicts and review recipient goal/task records before restart. Adding follow mode to independent history may require a deliberate merge with --allow-unrelated-histories; setup does not rewrite existing history. Fast-forward-only pull stops on diverged history. Full Access is unchanged.

Unattended first setup: SAPLING_GIT_MODE=local|own|upstream, own remote in SAPLING_GIT_REMOTE, optional initial branch in SAPLING_GIT_BRANCH. Mac version history requires Git (Apple Command Line Tools if missing); Windows Git Bash supplies it. Source ZIPs contain no .git metadata; the installer initializes it after your choice.
