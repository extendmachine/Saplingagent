Overview · Runtime · Interfaces

One restart for the complete project

Click Restart app to reload frontend,backends and project services from the current source. Keep the page and launcher open. Readiness is checked before the page refreshes; errors remain recoverable in-page. Conversations are not resent.

Adding a feature with AI

The AI implementing a persistent service also integrates its startup. You should not need a separate terminal for each generated project. Normal Node backends at backend/<service>/server.mjs, server.cjs or server.js are discovered on every restart. They bind process.env.PORT on loopback and provide /health. The runtime controller,stdio MCP and independent account setup service keep their existing infrastructure lifecycle.

Other directories,independent frontends,workers and other runtimes use the optional project-owned config/services.json file. Creating that file is part of the AI's implementation, not an extra user setup step. Dependencies install in the project before verification.

Startup manifest

{
  "version": 1,
  "services": [
    {
      "name": "reports",
      "cwd": "backend/reports",
      "command": ["node", "server.mjs"],
      "port": 4500,
      "healthPath": "/health",
      "dependsOn": ["workspace"]
    },
    {
      "name": "my-app",
      "cwd": "projects/my-app",
      "command": ["npm", "run", "dev", "--", "--host", "127.0.0.1", "--port", "${PORT}"],
      "port": 5400,
      "healthPath": "/",
      "dependsOn": ["reports"]
    }
  ]
}

Use a unique lowercase name (letters,digits,hyphens or underscores). A registration overrides automatic discovery of the same name; {"name":"reports","enabled":false} disables it. Built-in identities cannot be replaced by the manifest. Alternatively use file for a Node entrypoint plus optional args. Commands are argv arrays without an implicit shell; Node/npm use the running project Node. Other runtimes/executables must already be installed and explicitly configured. Windows batch scripts require an explicit command shell; normal npm registrations use Node directly.

cwd resolves from the application root. Command/args/env support literal ${ROOT} and ${PORT}. Keep secrets in local-secrets files, not command strings or manifest env values.

Readiness,ports and dependencies

dependsOn names services that must be ready first. Invalid definitions,missing dependencies,cycles and missing startup files/commands are rejected before stopping the working application. HTTP readiness uses a successful response (JSON ready:false keeps waiting). Registered services default to /; automatic Node backends use /health. healthCheck:"tcp" waits for a socket; healthCheck:"process" is for workers and only checks that the process stays alive. Optional timeoutMs is100–300000.

Preferred ports skip occupied listeners. Existing project ports remain stable when available, including when another service is added. Only owned processes are stopped. Each project receives PORT, SEED_SERVICE_PORT, SEED_SERVICE_PORTS (JSON mapping) and SEED_<SERVICE_NAME>_PORT; use these for inter-service addresses. The frontend also receives the map when it restarts.

Services with writes or background transactions should implement the shared runtime prepare/release protocol and set drain:true. Otherwise the runtime cannot detect their direct in-flight work. See runtime contract. Removed or disabled services stop and stay stopped at the next restart.

Fix and retry without exiting

Startup failures identify the service. Correct its source/configuration or install its dependencies, then click Restart app again; runtime recovery remains available through the live gateway. Full restart applies internal port edits while retaining the public/control addresses; new public address preferences apply on the next cold launch. The persistent controller/bootstrap itself is loaded at launch, so installing a different controller version requires that version's initial launch. Ordinary generated project changes only need Restart app.

SessionStorage draft recovery is best effort, but the active page retains a restart marker in memory and refreshes after readiness even when storage is unavailable. The main page provides only Restart app, which always restarts the complete managed project. There is no restart-options menu.
