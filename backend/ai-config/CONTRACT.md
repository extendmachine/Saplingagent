# AI configuration contract v1

TASK-20261012-001, Codex. The standalone setup service binds 127.0.0.1 at an OS-assigned port; it serves the compiled front/ai-config entry independently of chat. No persistent supervisor slot. Same-origin requests with X-Sapling-Config token from the HTML meta tag; reject other Host, Origin and cross-site Fetch Metadata. Token only protects setup HTTP and does not change Agent Full Access.

- GET /api/config/state: {revision,activeId,profiles,codex,login}. Profile summaries contain hasKey, never key material, credentials, email or arbitrary headers.
- POST /api/config/profiles: {revision?,id?,label,engine:codex|opencode,kind:api|chatgpt,protocol:responses|chat|anthropic,baseUrl,model,apiKey?,noAuth?,contextWindow?,maxOutput?,activate?}. Blank key retains a saved key; noAuth disables it for that edited profile while retaining the old private key. ChatGPT profile needs locally saved ChatGPT credentials. Creates/updates one scheme; no model request. Returns sanitized state. Version mismatch 409 CONFIG_CHANGED; invalid input 400 INVALID_CONFIG. Configuration is stored in local-secrets/ai-config/connections.json; API keys are local-secrets/api-keys/ai-<id>.json and referenced in the ledger. No key in public runtime config/TOML/CLI argv.
- POST /api/config/activate {revision?,id}: select an existing saved scheme; no current service restart/session mutation. New runtime/new conversation uses it.
- POST /api/config/models: profile draft fields above, saved id and optional apiKey. Explicit, bounded GET of <baseUrl>/models with matching auth. No prompt; no persistence. {models:[{id,name}]}; HTTP failure 502 PROVIDER_HTTP_ERROR with status, no raw body/key; timeout/transport 502 PROVIDER_UNREACHABLE; redirects not followed. IDs manual when endpoint lacks discovery.
- POST /api/config/login {mode:chatgpt|chatgptDeviceCode}: official pinned local Codex App Server auth flow, no password proxy. Returns {login:{phase,authUrl?,userCode?,mode}}; completion is polled through state. Login completion saves/selects ChatGPT scheme and registers credential reference. Only one login at a time (409 LOGIN_BUSY). App-server callbacks with another loginId are ignored. Late callbacks after cancellation/close do not activate a scheme.
- POST /api/config/login/cancel: cancel only the owned current auth flow.
- POST /api/config/close: close only setup service and its owned auth process, returning to launcher; running chat services stay as they are.

All responses no-store. JSON only, bounded body64KiB. Static assets served from explicitly built configuration UI, never arbitrary root files. Errors use {error:{code,message}} without raw upstream data. Disk/schema/lock errors are explicit; malformed files are preserved. Serial writes use an exclusive project-local writer lock, individually atomic key/ledger/profile publication (an I/O failure requires reloading actual state; this is not a cross-file transaction), stale locks are not silently broken. Saving is not quota/network/model/tool validation. Runtime contracts/ai-configuration.mjs translate private schemes to Codex args/env or OpenCode native provider config, retaining existing manual configuration and permissions. No dependency upgrades.

## Claude Agent engine (TASK-20261012-005–009)

Engine ID `claude` uses the project-local official Claude Agent SDK, with API-only Anthropic Messages profiles. Each conversation binds `engine`, `providerId` (`sapling-<profile-id>`) and `modelId`; existing bindings are immutable. Configuration accepts custom HTTP(S) API base URLs ending in `/v1`; SDK transport removes this trailing API version before its own `/v1/messages` route. Keys remain in local-secrets, never public responses. The default takes effect after restart. Local initialization checks MCP and Skills without a model prompt; authentication means a saved key, not proven quota. Streaming, completion, interruption and failure use existing chat events. Missing native sessions are reported, never silently replaced. Full Access and the completion-review receipt remain unchanged. No claude.ai subscription login is offered.
