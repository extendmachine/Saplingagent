## Decisions

Codex creation and selection permit modelId:string|null with providerId:null.
Same-Codex model-only selection uses the existing idle atomic compare-and-swap
endpoint, increments both revisions and preserves its native thread, logical
conversation content, requests and archived bindings. It clears contextUsage and
modelUsage. Existing pending/delivered handoff metadata retains identity/cutoff/
state and receives the new bindingRevision; completed old requests cannot deliver
a pending new binding. No synthetic history, new handoff or archive entry is
created for this case. Other engine/provider/model switches retain existing fresh
native binding semantics. Full history does not prevent a non-archiving model
change. Repeated same selection preserves file bytes.

The standard PATCH accepts modelUsage:null or exactly five documented fields:
requestedModel, actualModel, requestId, updatedAt and source. Limits are240/240/160
characters for the respective strings, no control characters; updatedAt must be
canonical UTC ISO as generated by Date.toISOString. Evidence source is one of
thread/start, thread/resume, model/rerouted or unreported; unreported requires
actualModel:null. Missing actual model is never guessed. Omission preserves prior
evidence; null clears it. Legacy files are not rewritten on read; malformed stored
evidence refuses with CORRUPT_STORAGE and unchanged bytes. Old binding snapshots
remain rejected by expectedEngineRevision. The generic HTTP routes already pass
and serialize session fields, so server.mjs needs no implementation change.
