## Goal and scope

Keep a logical session's identity, messages, title, attachments and request history
when its user explicitly switches Codex, Claude or OpenCode. Store native binding
history, reject unsafe concurrent/stale writes, and retain pending handoff metadata
across failed turns and service restart.

Only backend/workspace source, contract, service/deployment documentation, tests and
this handoff are changed. Root indexes, Agent/frontend/kernel/provider code,
version/manifest, credentials, real conversations, customer projects and release
are outside this task. The user authorized main only; no customer synchronization
or release promotion is inferred.

## Decisions and interface

POST /sessions/:id/engine requires full selection plus expectedRevision and
expectedEngineRevision. It joins the existing single-writer queue and atomic file
replacement, rejects busy records, and archives the old binding before clearing
threadId/contextUsage and incrementing engineRevision. Returning to an old engine
still starts a fresh native session. Same-selection requests are no-ops. At1000
history entries further switches fail explicitly without pruning old native IDs.

Legacy reads add engineRevision0/history[]/handoffnull only in memory. The session
list exposes engineRevision. Ordinary PATCH keeps selection immutable and rejects
arbitrary switching metadata replacements. Optional expectedEngineRevision guards
all new Agent snapshots. Requests gain optional engineRevision (legacy absence0);
an existing ledger entry cannot change binding or point to a future one.

A nonempty history produces a pending handoff with an explicit last-message cutoff.
The dedicated acknowledgement field handoffDeliveredRequestId requires a matching
completed request in the current binding and an expectedEngineRevision guard. The
same atomic snapshot records delivery, so failed writes retain pending metadata.
An already-delivered acknowledgement is idempotent only for the same request and
current binding with completed status, so a lost successful response can be retried
without turning the handoff back to pending or changing its delivery owner. Actual
history rendering, quoting, model acceptance and retries belong to Agent. Native
ID creation alone is not treated as delivery; no exactly-once model claim.
