## 关键决定

1. `turnTimeoutMs`默认及缺省0，只有正值创建硬截止timer；`turnIdleWarningMs`默认600000，0关闭提醒。两者均拒绝非整数/负数/NaN/Infinity/字符串/null/大于2147483647，避免Node把无效timer当1ms。
2. 独立单轮monitor只保存时间、类别、状态、item lifecycle ID及计划去重hash；非空文本/推理/计划delta、不同有效计划更新、有效item生命周期、命令outputDelta及MCP progress.message是真实进展。重复生命周期和相同计划不续期；心跳/轮询/重连/保存/error retry不续期。
3. 闲置每段一次status.label，不发error/done，不中断、不自动模型重发；有效进展恢复继续并重新计时。静默工具仍能显示tool-running。现有单页能读status，无front变更；新订阅重放当前闲置提示。
4. 公开session可额外带可选progress对象，当前活动轮的内存元数据，结束省略；不改workspace schema、不持久化、不返回推理/命令输出/MCP进度原文或敏感参数，不宣称断点续跑。
5. turn/start RPC返回确认turnId前通知等待run.turnReady；返回后重新检查run及thread映射，归一化`params.turnId ?? params.turn.id`并严格匹配。旧nested completion/started不能绑定、续期或结束新轮。
6. 兼容已绑定人工请求可区分waiting-user；当前Full Access标准确认实际自动批准，非标准自由问题仍拒绝，未新增人工问题界面。没有通过无turnId的thread status推断本轮，避免旧事件误标。
7. 初始保存、thread start/resume及preferences等等待返回后检查finished、active身份、closing和cancelRequested，已结束/已替换轮不创建monitor、不重建App Server或发turn/start；启动前手动取消按interrupted完成；显式硬限在setup等待期间触发时保留abortError，以failed和原始总时限error收尾，不误标人工取消。新增7项延迟初始保存断连及thread start/resume/preferences等待中断连/取消回归，均确认零新模型轮与零遗留timer；另有setup等待期间硬限后释放偏好请求的回归，确认failed+总时限error、零turn/start/零timer。
8. Stop仍真实interrupt；显式正硬时限仍真实中断。monitor独立，结束/失败/取消/disconnect/shutdown停止timer，既有保存/退出生命周期保持。
