# Runtime deployment

Launch via `Saplingagent.sh start` after project installation/login, or project-local Node `scripts/dev.mjs` for development. First adoption requires stopping the previous launcher and starting the new one once. The manager itself has no install step. Keep the launch window open.

Configured loopback listeners: public gateway frontPort5173, internal Vite vitePort5174, control runtimeManagerPort4314, Agent4310, workspace4311, builder4312, optional PDF4313. Check free ports before starting; foreign owners are never killed. PDF is unnecessary on main and only launched when its selected source exists. New branch dependencies must be installed first. The gateway keeps the same browser origin during frontend/backend restart, streams SSE, and forwards Vite WebSocket upgrades.

Select a branch or historical version, then Restart app. Restart backend retains Vite. Recovery URL: `/__saplingagent/runtime`; it remains available if frontend/Agent startup fails or an older UI lacks controls. Repair the selected source, dependency installation, configuration or login then retry. Changed ports or manager/launcher code require Control+C and running the operating-system launcher again. Reloading the manager is not supported by its own button.

Startup health budgets are 20 seconds per service and 120 seconds for authenticated Agent/MCP; they do not limit AI turns. Shutdown terminates only owned groups with TERM, four-second wait and bounded KILL fallback. Manual SIGKILL cannot guarantee cleanup. No automatic restoration of source or application data. Legacy direct backend callers are outside gateway accounting; finish their operations before restarting an older version. Current UI restores an unsent draft; older UIs may not. Persisted workspace sessions and credentials are retained.

## Windows x64 candidate (TASK-20261011-030)

Native Windows10/11 x64 uses the shared contracts/local-process.mjs OS contract. Project Node and native executable dependencies remain local. App Server uses codex.exe with file credential storage; OpenCode uses its selected opencode.exe, local XDG data/config/cache/state. The manager and command cancellation stop only their owned live PID trees with taskkill /PID /T /F; POSIX detached process-group behavior is retained. Windows shell commands use ComSpec cmd.exe /d /s /c, regardless of an inherited Git Bash SHELL. HTTP/SSE/permissions remain unchanged, including Full Access. Windows forced termination is abrupt; finish active operations before restart, and externally detached programs or forced parent death cannot guarantee cleanup. Native Windows10 auth/model/restart acceptance is pending; current host checks are macOS/synthetic. Start with bash Saplingagent.sh in Windows Git Bash; platform guide ../../docs/windows-install.html. No actual credentials, global environment or running production processes are changed by this candidate.
