# Runtime lifecycle and gateway contract

The operating-system launcher owns one persistent runtime manager. `frontPort` (5173) is its same-origin streaming HTTP/WebSocket gateway; Vite runs on `vitePort` (5174). `runtimeManagerPort` (4314) also exposes loopback control. The gateway survives frontend and backend restarts. No arbitrary commands, paths or PIDs are accepted.

- GET `/api/runtime/status`: instanceId, generation, phase, busy, canRestart, jobId, scope, services [{name,pid,running}], error {code,message,service?}.
- POST `/api/runtime/restart`: optional JSON `{scope: "all" | "backend"}`; defaults to all. 202 returns jobId/status. Concurrent requests share one job. All stops/relaunches frontend and all owned backends; backend preserves frontend. Generation advances only after selected components, authenticated Agent and MCP are ready.
- GET `/__saplingagent/runtime`: persistent English recovery/control page with status, restart choices and Open app. It works even if a selected older UI has no restart button or Vite fails. Non-control `/api/*` streams to Agent; other HTTP/WebSocket traffic goes to internal Vite without buffering SSE.
- Internal POST `/internal/runtime/prepare` and `/internal/runtime/release`: existing Bearer token required on each backend. Prepare atomically refuses active writes, AI, Git operations or unsaved sessions; prepared services reject new mutations with 503. Shared gate is `contracts/runtime-drain.mjs`.

While preparing/restarting, the gateway rejects new ordinary mutations. Outstanding gateway writes refuse restart; supported services also gate direct authenticated callers. Legacy versions lacking drain endpoints use Agent session-running checks and gateway accounting. This fallback cannot observe direct legacy backend callers; finish their work first. A branch switch is a separate Git operation; choose a version first, then Restart app. Dirty files are saved by the existing Git switch API. No automatic chat resend, rollback, root elevation or new MCP protections.

The current checkout determines service entrypoints on every restart. PDF is optional and launched only if its source exists. Changed port assignments or manager/launcher source require closing the launch window and running the operating-system launcher again. Dependencies newly introduced by a branch must be installed with its installer before restarting. Older frontend versions may not implement draft restoration; persisted sessions and project credentials remain on disk.

`openCodePort` defaults to 4315 and is reserved as a distinct loopback port. OpenCode remains an Agent-owned child process, so backend/all restart and Agent shutdown terminate only that owned process group. The manager passes the selected port to Agent and does not expose OpenCode directly through the public gateway.

Only manager-owned child process groups are stopped. Failed startup remains observable and retryable through the gateway, including frontend failure. Same configured loopback Host/Origin rules apply to control and proxy traffic; script mutations require Bearer authentication. No CORS or browser token exposure. Responses/logs omit credentials, conversation content and raw child diagnostics. Lifecycle deadlines bound startup/shutdown, not AI turns.

## Windows x64 candidate (TASK-20261011-030)

Native Windows10/11 x64 uses the shared contracts/local-process.mjs OS contract. Project Node and native executable dependencies remain local. App Server uses codex.exe with file credential storage; OpenCode uses its selected opencode.exe, local XDG data/config/cache/state. The manager and command cancellation stop only their owned live PID trees with taskkill /PID /T /F; POSIX detached process-group behavior is retained. Windows shell commands use ComSpec cmd.exe /d /s /c, regardless of an inherited Git Bash SHELL. HTTP/SSE/permissions remain unchanged, including Full Access. Windows forced termination is abrupt; finish active operations before restart, and externally detached programs or forced parent death cannot guarantee cleanup. Native Windows10 auth/model/restart acceptance is pending; current host checks are macOS/synthetic. Start with Saplingagent.ps1; platform guide ../../docs/windows-install.html. No actual credentials, global environment or running production processes are changed by this candidate.
