# Kernel version and source publication

Since the owner's2026-10-19 correction, Saplingagent has one version, **kernel0.9.5**. The installed `kernel/manifest.json` version is authoritative. Git branches, source SHAs and application names identify source/customer projects, not another Saplingagent version. Do not invent a separate product version.

The setup page, standalone controls, footer, Bash menu and downloader use this manifest. Missing/invalid installed metadata is unavailable; the historical0.90 baseline is diagnostics only. `GET /api/release`, `config/release.json`, and receipt fields `releaseVersion`/`productVersion` remain deprecated wire/metadata aliases for older tools. Current displays do not use a separate product label. The new `/api/release` implementation reads the kernel manifest first; only pre-kernel legacy apps use its old file fallback. A kernel update may leave a legacy compatibility file untouched, so it is not runtime authority.

Maintainer sequence: freeze code; set the owner-selected three-part version in kernel/manifest.json; run `node kernel/build-manifest.mjs --maintainer` to synchronize build-time package/lock/config mirrors and hashes; run `--check`; test; integrate main first; promote to release only when requested, preserving showcase content. `node kernel/scripts/verify-release.mjs --ref release --main MAIN_SHA --version 0.9.5` verifies committed identity, mirrored metadata, complete hashes and code equality. Source packages and bootstrap receipts expose kernelVersion0.9.5 plus the exact sourceCommit; releaseVersion is an equal compatibility alias.

A branch push is not a formal GitHub Releases publication. Create a new immutable tag and publish assets only in authorized publication scope, then verify tag/release/download correspondence. Preserve existing tags and history; an explicitly authorized mistaken-label correction needs old-target evidence and expected-old-value checks. Never describe a tag alone as published assets.

Old labels0.90/0.91/0.92 are recognized by the new comparator as0.9.0/0.9.2/0.9.3, without rewriting old manifests or backups. Their shipped updaters consider0.9.4 a downgrade. Use the new tooling's explicit `kernel/cli.mjs --root TARGET check/update` once, as documented in docs/kernel-version-migration.html. Live-target checks, conflicts, explicit update risk acknowledgement, backups and manual restoration remain. Do not regenerate a recipient baseline or overwrite custom app/core edits.
