## User goal and behavior

Replace the five numbered .command files with Saplingagent.command. Its menu runs before Node is installed and offers Install / update, Configure AI, Start app, Diagnostics and Quit. Configure AI offers the existing Codex account login and OpenCode provider/API-key setup. Internal bootstrap/CLI helpers remain in the complete application folder.

Explicit install/login/opencode/start/doctor/logout actions and repair/device-auth/no-open flags use the same launcher. Completed or failed menu actions return to the menu; EOF exits; INT/TERM/HUP are forwarded to the owned child and the menu waits for termination. OpenCode auth uses the existing command runner for cancellation and does not report a cancelled setup as saved.

## Compatibility and limits

The five numbered launchers and internal entry.sh are replaced; current docs, installer chmod checks, package allowlist/required entries and recipient instructions use the new launcher. Older checked-out versions retain their original launchers in history. Credentials remain project-local and no global authentication is imported. Current startup still requires Codex login; OpenCode is an additional selected engine. Custom endpoint/model configuration remains a separate provider configuration, not a new wizard.
