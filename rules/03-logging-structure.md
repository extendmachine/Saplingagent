# 03. Independent log directory and division by service

## Target

Each project must have a separate `logs/` folder to centrally record the logs of each microservice. Logs are divided into subdirectories by service, one microservice and one folder, one log file per day, and kept for 30 days, which is convenient for retrieval, cleaning and troubleshooting.

## Recommended directory structure

```text
logs/
├── service-a/
│   └── service-a-YYYY-MM-DD.log
├── service-b/
│   └── service-b-YYYY-MM-DD.log
└── service-c/
    └── service-c-YYYY-MM-DD.log
```

## AI execution rules

1. Each service can only be written to its own log subdirectory.
2. Log file naming is recommended to include service name and date, such as `service-a-2026-07-10.log`.
3. Each service only generates the log file corresponding to the day every day, and does not mix it with other date files.
4. Logs are kept for 30 days by default, and logs exceeding 30 days should be cleaned up automatically or regularly.
5. When adding new services, the corresponding log directory planning should be established synchronously.
6. Add `logs/` to `.gitignore`; real log files must not enter Git.
7. If you want to keep the directory structure, you can use `.gitkeep`, but do not submit the real log content.
8. New projects or new services record the log plan in the "Log Scheme Filling Format" below, and the final content is directly written to the `SERVICE.md` of the service.
9. Standardize the source directory pre-built `logs/README.md` as a secure empty skeleton and copied with the whole package; no real log files should appear in it, and the real logs generated by the target project continue to be ignored by Git.

## Log scheme filling format

Directly maintain the following in the microservice `SERVICE.md` without creating separate template files:

```markdown
## Daily record

- Service: `<SERVICE_NAME>`
- Log directory: `logs/<service-name>/`
- File name: `<service-name>-YYYY-MM-DD.log`
- Ordinary log retention: 30 days
- Cleaning method: <start-up time / scheduled task / manual maintenance>
- Log level: <DEBUG / INFO / WARN / ERROR>
- Error association field: <request_id / task_id / trace_id>
```

## Prohibited matters

- It is forbidden for multiple services to write the same log file.
- It is forbidden to accumulate ordinary running logs for more than 30 days for a long time.
- It is forbidden to submit the real running log to git.
- It is forbidden to write sensitive information to the log.
