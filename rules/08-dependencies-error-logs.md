# 08. 依赖管理、错误处理与日志等级

## 目标

每个微服务可以独立管理依赖，但新增依赖必须有明确原因。错误处理和日志输出要可排查、可维护，并禁止写入敏感信息。

## 依赖管理

1. 微服务依赖文件应放在该微服务目录内。
2. 新增依赖前，先确认该依赖是否确实必要。
3. 不为了小功能引入体积大、维护成本高或用途不清晰的依赖。
4. 新增依赖后，必须在该微服务的 `SERVICE.md` 中记录用途。
5. 不同微服务可以有不同依赖方案，不强制统一技术栈。

## 错误处理

1. 错误信息必须能帮助定位问题。
2. 对外错误应保持清晰，不暴露敏感信息。
3. 微服务接口建议有稳定错误码或错误说明。
4. 发生跨服务错误时，应能看出是哪个服务、哪个接口、哪个步骤失败。

## 日志等级

建议使用以下等级：

1. `info`：正常运行信息。
2. `warn`：可恢复或需要关注的问题。
3. `error`：执行失败、接口失败、数据异常等需要处理的问题。

## 日志安全

1. 禁止在日志中写入密码、token、API key、SSH key、服务器登录密钥。
2. 禁止在日志中输出完整本地敏感信息文件内容。
3. 客户内容不默认视为敏感内容，但如业务明确要求脱敏，应按业务规则处理。
4. 日志应按 `rules/03-logging-structure.md` 存放和清理。
